`@shadcn/helpers/tanstack-ai` 를 쓰면 AI 대화를 코드로 적어 TanStack AI 의 `useChat` 으로
흘려보낼 수 있습니다. 모델도 API 라우트도 네트워크 요청도 API 키도 필요 없습니다.

TanStack 고유의 `UIMessage[]` 값을 만들고, 어시스턴트 응답을 로컬 연결 어댑터를 통해
실제 AG-UI 이벤트로 다시 재생합니다. 그래서 컴포넌트가 운영 환경과 똑같이 움직입니다.
글과 추론은 한 낱말씩 흐르고, 도구 호출은 입력에서 결과로 넘어갑니다.

```ts showLineNumbers
import { createChat } from "@shadcn/helpers/tanstack-ai"

const chat = createChat()
  .user("What changed in this release?")
  .assistant("The release adds keyboard shortcuts and faster search.")
  .user("Can you show me the shortcuts?")
  .assistant("Press ⌘K to search and ⌘Enter to submit.")
```

처음 메시지와 로컬 연결을 함께 `useChat` 에 넘기세요. TanStack AI 는 서버에서 받았을
것과 똑같은 AG-UI 이벤트를 받습니다.

```tsx showLineNumbers
import { useChat } from "@tanstack/ai-react"

function Chat() {
  const { messages, append } = useChat({
    initialMessages: chat.get(0), // starts with no messages.
    connection: chat.transport(),
  })

  const nextMessage = chat.next(messages)

  return (
    <button
      disabled={!nextMessage}
      onClick={() => {
        if (nextMessage) {
          void append(nextMessage)
        }
      }}
    >
      Send next message
    </button>
  )
}
```

`get(0)` 은 메시지 없이 시작합니다. `append(nextMessage)` 로 다음 사용자 메시지를 더하면
연결이 그에 대한 어시스턴트 응답을 AG-UI 이벤트로 흘려보냅니다.

---

## What It's For

이 도우미는 채팅 UI 를 모델·백엔드와 떼어 놓아 프론트엔드만 따로 만들 수 있게 합니다.
연결 없이도 곧바로, 언제나 똑같이 동작합니다.

- **컴포넌트 만들기.** 모델을 붙이지 않고도 실제 같은 스트리밍 출력으로 말풍선·도구
  카드·추론 패널을 만듭니다.
- **미리 보기와 시연.** 모델에 기대지 않는, 언제나 같은 미리 보기·스크린샷·영상을
  만듭니다.
- **문서 쓰기.** 열 때마다 똑같이 그려지는 대화로 문서 예시를 채웁니다.
- **테스트.** 네트워크 호출도, 토큰 비용도, 들쭉날쭉한 모델 출력도 없이 CI 에서 항상
  같은 스트림을 검증합니다.

## Usage

대화를 만들고 그 메시지와 연결을 `useChat` 에 넘긴 뒤, `next()` 로 미리 적어 둔 사용자
메시지를 하나씩 보냅니다.

```tsx showLineNumbers {3-4,6-10,12-13,16-21,28-34}
"use client"

import { createChat } from "@shadcn/helpers/tanstack-ai"
import { useChat } from "@tanstack/ai-react"

const chat = createChat()
  .user("What changed in this release?")
  .assistant("The release adds keyboard shortcuts and faster search.")
  .user("Can you show me the shortcuts?")
  .assistant("Press ⌘K to search and ⌘Enter to submit.")

const initialMessages = chat.get(0)
const connection = chat.transport()

export function Chat() {
  const { messages, append, status } = useChat({
    initialMessages,
    connection,
  })
  const nextMessage = chat.next(messages)
  const isBusy = status === "submitted" || status === "streaming"

  return (
    <div>
      {messages.map((message) => (
        <div key={message.id}>{/* Render the message */}</div>
      ))}
      <button
        disabled={!nextMessage || isBusy}
        onClick={() => {
          if (nextMessage && !isBusy) {
            void append(nextMessage)
          }
        }}
      >
        Send
      </button>
    </div>
  )
}
```

## User Messages

이 도우미로 더한 메시지는 `user` 와 `assistant` 역할을 씁니다. 사용자 메시지는
`user()` 로 더합니다. `createChat({ messages })` 로 시작하면 원래 있던 TanStack 메시지는
그대로 남습니다.

```ts
const chat = createChat().user("What changed in this release?")

const [message] = chat.get()

message.role // "user"
message.parts // [{ type: "text", content: "What changed in this release?" }]
```

필요하면 두 번째 인자로 `id` 를, 또는 `metadata` 를 통해 `createdAt` 시각을 넘기세요.

```ts
chat.user("What changed in this release?", {
  id: "user-release-question",
  metadata: {
    createdAt: "2026-01-01T10:00:00.000Z",
  },
})
```

사용자 메시지에는 파일도 담을 수 있습니다. [파일](#files)을 보세요.

## Assistant Messages

어시스턴트 메시지는 `assistant()` 로 더합니다.

```ts
const chat = createChat().assistant(
  "The release adds keyboard shortcuts and faster search."
)

const [message] = chat.get()

message.role // "assistant"
message.parts // [{ type: "text", content: "The release adds..." }]
```

문자열을 넘기면 텍스트 조각 하나가 만들어집니다. TanStack 메시지 조각의 배열을 넘겨도
됩니다.

```ts
chat.assistant([
  { type: "thinking", content: "I should summarize the release." },
  { type: "text", content: "The release adds keyboard shortcuts." },
])
```

메시지를 더 잘게 나눠 흘려보내고 싶다면 writer 콜백을 쓰세요.

```ts
chat.assistant(({ writer }) => {
  writer.reasoning("I should summarize the release.")
  writer.text("The release adds keyboard shortcuts and faster search.")
})
```

writer 는 부른 순서대로 조각을 더합니다.

## Message Parts

TanStack writer 는 AG-UI 연결을 오갈 수 있는 조각, 곧 텍스트·추론·도구 호출을
지원합니다. 시간 조절과 오류도 다룰 수 있습니다.

```ts
chat.assistant(({ writer }) => {
  writer.reasoning("I should answer directly.")
  writer.text("Hello.")
})
```

이 연결에 대응되는 것이 없는 조각은 [어댑터 차이](#adapter-differences)를 보세요.

---

## Text

글은 `text()` 로 더합니다.

```ts
chat.assistant(({ writer }) => {
  writer.text("The release adds keyboard shortcuts.")
  writer.text(" Search is faster too.")
})
```

`chat.transport()` 와 함께 쓰면 글이 한 낱말씩 흐릅니다. `text()` 를 잇달아 부르면
`get()` 에서는 조각이 따로 나오지만, 재생할 때 TanStack 의 스트림 처리기가 텍스트 조각
하나로 합칩니다.

값을 한 번에 보내려면 `mode: "instant"` 를, 글자가 나오는 간격을 바꾸려면 `delayMs` 를
쓰세요.

```ts
writer.text("Done.", { mode: "instant" })
writer.text("This part streams more slowly.", { delayMs: 100 })
```

---

## Reasoning

추론은 `reasoning()` 으로 더합니다. TanStack 의 `thinking` 조각이 됩니다.

```ts
chat.assistant(({ writer }) => {
  writer.reasoning("I should check the latest conditions first.")
  writer.text("Let me check the weather.")
})
```

추론도 텍스트와 똑같이 `delayMs` 와 `mode` 옵션을 씁니다.

```ts
writer.reasoning("Checking the forecast.", { mode: "instant" })
```

## Tool Calls

도구 호출은 `tool()` 로 더합니다. 입력부터 출력까지 그 도구를 따라다니는 핸들을
돌려줍니다.

```ts
chat.assistant(({ writer }) => {
  writer
    .tool("getWeather", {
      input: { city: "San Francisco" },
    })
    .sleep(900)
    .output({
      city: "San Francisco",
      temperature: 18,
      condition: "Breezy",
    })

  writer.text("It is 18°C and breezy in San Francisco.")
})
```

도구는 `output()` 이나 `error()` 로 끝냅니다.

```ts
writer.tool("getWeather", { input: { city: "San Francisco" } }).error()
```

완성된 TanStack 메시지에는 `tool-call` 조각과 그 옆의 `tool-result` 조각이 담깁니다.

앱에서 쓰는 것과 같은 클라이언트 도구 튜플을 넘기면 도구 이름·입력·출력에 타입이
붙습니다.

```ts
import { clientTools } from "@tanstack/ai-client"

import { getWeatherTool } from "@/lib/tools"

const tools = clientTools(getWeatherTool.client())
const chat = createChat<typeof tools>()

chat.assistant(({ writer }) => {
  writer
    .tool("getWeather", {
      input: { city: "San Francisco" },
    })
    .output({
      city: "San Francisco",
      temperature: 18,
      condition: "Breezy",
    })
})
```

## Files

사용자 메시지에 파일을 넣을 때는 `files` 옵션을 씁니다.

```ts
chat.user("Describe this image.", {
  files: [
    {
      mediaType: "image/png",
      url: "https://example.com/screenshot.png",
    },
  ],
})
```

도우미는 파일마다 미디어 타입에 따라 TanStack 미디어 조각으로 바꿉니다.

| Media type | TanStack part |
| ---------- | ------------- |
| `image/*`  | `image`       |
| `audio/*`  | `audio`       |
| `video/*`  | `video`       |
| Other      | `document`    |

이 조각들은 `get()` 으로 얻을 수 있습니다. `next()` 가 사용자 `UIMessage` 전체를
돌려주므로 `append()` 를 써도 글과 미디어 조각이 그대로 남습니다.

```ts
const nextMessage = chat.next(messages)

if (nextMessage) {
  void append(nextMessage)
}
```

어시스턴트의 미디어 조각은 고정된 조각 배열에 담아 `get()` 으로 읽을 수 있지만, AG-UI
연결은 어시스턴트 파일을 흘려보내지 않습니다.

## Adapter Differences

TanStack AI 와 AI SDK 는 메시지와 스트리밍 방식이 다릅니다. 이 어댑터는 처음부터 끝까지
온전히 표현할 수 있는 것만 내놓습니다.

| Feature                               | Behavior                                                                   |
| ------------------------------------- | -------------------------------------------------------------------------- |
| Text                                  | Streams as AG-UI text and becomes a `text` part.                           |
| Reasoning                             | Streams as AG-UI reasoning and becomes a `thinking` part.                  |
| Tool calls                            | Stream input, output, and errors into `tool-call` and `tool-result`.       |
| Data and structured output            | No writer method; existing message parts remain available through `get()`. |
| Custom events                         | No writer method in the public adapter.                                    |
| Sources, reasoning files, step starts | No TanStack message or AG-UI equivalent in this adapter.                   |
| Assistant files                       | Available in `get()`, but omitted from connection streams.                 |
| Stop                                  | Closes the stream; AG-UI has no separate abort event.                      |

AI SDK 의 메시지 조각 구조를 온전히 써야 한다면 [AI SDK 도우미](/docs/helpers/ai-sdk)를
쓰세요.

## Reading Messages

대화 처음부터의 메시지를 얻으려면 `get()` 을 씁니다.

```ts
chat.get() // Every message.
chat.get(2) // The first two messages.
chat.get(0) // An empty initial conversation.
```

`get()` 은 TanStack `UIMessage[]` 를 복제해 돌려주며 채팅을 바꾸지 않습니다.

이미 보여 준 메시지 다음에 올, 미리 적어 둔 사용자 메시지는 `next()` 로 찾습니다.

```ts
const initialMessages = chat.get(2)
const nextMessage = chat.next(initialMessages)
```

`next()` 는 색인이 아니라 언제나 메시지 기록을 받습니다. 다음 사용자 메시지를 돌려주고
남은 것이 없으면 `null` 을 돌려줍니다.

## Start from Existing Messages

저장해 둔 대화나 픽스처에서 이어 가려면 `messages` 를 넘기세요.

```ts
import { createChat } from "@shadcn/helpers/tanstack-ai"
import type { UIMessage } from "@tanstack/ai-client"

declare const savedMessages: UIMessage[]

const chat = createChat({ messages: savedMessages })
  .user("What should we do next?")
  .assistant("Turn the open questions into a checklist.")
```

원래 있던 ID·시각·조각은 그대로 남습니다.

## Transport

`transport()` 는 `useChat` 의 `connection` 으로 넘길 TanStack `ConnectConnectionAdapter`
를 만듭니다.

```ts
const connection = chat.transport()

const { messages, append, sendMessage } = useChat({
  initialMessages: chat.get(0),
  connection,
})

const nextMessage = chat.next(messages)

// Replay the next predefined user message.
if (nextMessage) {
  void append(nextMessage)
}

// Or send ordinary user input as text or multimodal content.
void sendMessage("Tell me more.")
```

`append()` 나 `sendMessage()` 로 실행이 시작되면 연결이 현재 기록 다음에 올 어시스턴트
메시지를 찾아 TanStack 의 평소 스트림 처리기로 AG-UI 이벤트를 내보냅니다. 먼저 메시지
ID 로 맞춰 보고, 안 되면 마지막 메시지의 역할과 글을 견줍니다.

미리 적어 둔 사용자 메시지를 다시 보내려면 `append(nextMessage)` 를 쓰세요. 그 메시지의
ID 와 미디어 조각이 그대로 남습니다. 평범한 사용자 입력에는 `sendMessage()` 를 씁니다.
`UIMessage` 전체 대신 문자열이나 여러 형식의 내용을 받습니다.

### Events

응답은 아래 순서로 이벤트를 낼 수 있습니다.

```txt
RUN_STARTED
REASONING_MESSAGE_START → REASONING_MESSAGE_CONTENT → REASONING_MESSAGE_END
TOOL_CALL_START → TOOL_CALL_ARGS → TOOL_CALL_END → TOOL_CALL_RESULT
TEXT_MESSAGE_START → TEXT_MESSAGE_CONTENT → TEXT_MESSAGE_END
RUN_FINISHED
```

미리 적어 둔 오류는 `RUN_ERROR` 를 냅니다. 실행마다 쓰이는 `threadId` 와 `runId` 는
TanStack 이 넣어 줍니다.

### Options

| Option     | Type                                     | Default | Description                                                                       |
| ---------- | ---------------------------------------- | ------- | --------------------------------------------------------------------------------- |
| `delayMs`  | `number`                                 | `50`    | 글자와 추론이 조금씩 나올 때의 간격입니다. `0` 이나 `undefined` 를 주면 없앱니다. |
| `fallback` | `string`, `MessagePart[]`, or a callback | None    | 미리 적어 둔 어시스턴트 응답이 남지 않았을 때 흘려보낼 응답입니다.                |

연결에 준 `delayMs` 는 흐르는 모든 텍스트·추론 조각의 기본값입니다. 조각 하나만 다르게
하려면 `writer.text(..., { delayMs })` 나 `writer.reasoning(..., { delayMs })` 를
쓰세요.

```ts
const connection = chat.transport({
  delayMs: 25,
})
```

### Fallback

미리 적어 둔 응답이 다 떨어졌을 때는 `fallback` 을 쓰세요. 그러면 시연을 계속 쓸 수
있습니다.

```ts
const connection = chat.transport({
  fallback: "This demo has no more predefined replies.",
})
```

fallback 에는 TanStack 메시지 조각 배열이나 writer 콜백을 넘길 수도 있습니다. 콜백은 들어온
대화 기록을 받으므로 현재 상태에 맞는 응답을 만들 수 있습니다.

```ts
const connection = chat.transport({
  fallback: ({ writer, messages }) => {
    writer.text(`This example already has ${messages.length} messages.`, {
      mode: "instant",
    })
  },
})
```

fallback 응답은 어시스턴트 응답처럼 흐르지만 미리 적어 둔 대화에는 더해지지 않습니다.
fallback 이 없으면 대화가 다 떨어졌을 때 연결이
`"No assistant response found for this transcript."` 예외를 던집니다.

`useChat` 의 `stop()` 을 부르면 흐르던 연결 스트림이 닫힙니다.

## Timing

실제 응답의 속도감을 내려면 지연을 주세요.

```ts
const chat = createChat()
  .user("Give me a project update.")
  .sleep(800)
  .assistant(({ writer }) => {
    writer.reasoning("I should lead with the completed milestone.")
    writer.sleep(500)
    writer.text("The first milestone is complete.", { mode: "instant" })
  })

const connection = chat.transport({ delayMs: 50 })
```

- `chat.sleep(ms)` 는 다음 어시스턴트 응답이 시작하기 전에 기다립니다.
- `writer.sleep(ms)` 는 어시스턴트 응답의 조각 사이에서 기다립니다.
- `tool.sleep(ms)` 는 도구의 입력과 결과 사이에서 기다립니다.
- `transport({ delayMs })` 는 텍스트·추론이 조금씩 나올 때의 기본 간격을 정합니다.
- `writer.text(text, { delayMs })` 와 `writer.reasoning(text, { delayMs })` 는 조각
  하나의 간격만 바꿉니다.
- `mode: "instant"` 는 텍스트나 추론 값을 한 번에 보냅니다.

테스트를 빠르게 돌리려면 `chat.transport({ delayMs: 0 })` 과 즉시 출력을 쓰세요.

## Errors

어시스턴트 응답 전체가 실패해야 한다면 채팅에서 `error()` 를 부르세요.

```ts
const chat = createChat()
  .user("Load the report.")
  .error("The report could not be loaded.")
```

TanStack 의 `RUN_ERROR` 이벤트를 냅니다.

다른 내용이 다 흐른 뒤에 실패시키려면 `writer.error()` 를 쓰세요.

```ts
chat.assistant(({ writer }) => {
  writer.text("I found the report.")
  writer.error("The connection closed before it could be read.")
})
```

## Metadata and IDs

TanStack 메시지는 `createdAt` 시각을 지원합니다. 메시지 메타데이터로 넘기면
`get()` 과 `next()` 를 거쳐도 그대로 남습니다. AG-UI 연결은 메시지 메타데이터를
흘려보내지 않습니다.

```ts
const chat = createChat()
  .user("Hello", {
    metadata: { createdAt: "2026-01-01T10:00:00.000Z" },
  })
  .assistant("Hi.", {
    id: "assistant-welcome",
    metadata: { createdAt: new Date("2026-01-01T10:00:01.000Z") },
  })
```

접두사를 바꾸거나 시각을 고정해야 한다면 채팅 옵션을 쓰세요.

```ts
const chat = createChat({
  messageIdPrefix: "demo-message",
  toolCallIdPrefix: "demo-tool",
  now: "2026-01-01T00:00:00.000Z",
})
```

## API Reference

위에서 자주 쓰는 흐름을 다뤘습니다. 여기서는 공개된 것을 모두 정리합니다
export and option.

### `createChat()`

타입이 붙은 대화를 만들고 연쇄 호출용 TanStack 채팅을 돌려줍니다.

```ts
function createChat<
  TOOLS extends ReadonlyArray<AnyClientTool> = AnyClientTool[],
  DATA = unknown,
>(options?: CreateChatOptions<TOOLS, DATA>): TanStackChat<TOOLS, DATA>
```

#### Type Parameters

| Parameter | Description                                                                  |
| --------- | ---------------------------------------------------------------------------- |
| `TOOLS`   | 도구 이름·입력·출력에 타입을 붙이는 데 쓰는 클라이언트 도구 튜플입니다.      |
| `DATA`    | 이미 있는 TanStack 메시지의 `structured-output` 조각이 담는 값의 타입입니다. |

도우미의 writer 는 `structured-output` 조각을 만들지 않습니다. 이미 있는 메시지에서
시작할 때 `DATA` 가 그 타입을 지켜 줍니다.

#### Options

| Option             | Type                       | Default                      | Description                                              |
| ------------------ | -------------------------- | ---------------------------- | -------------------------------------------------------- |
| `messages`         | `UIMessage<TOOLS, DATA>[]` | `[]`                         | 이미 있는 대화 기록에서 시작합니다. 메시지는 복제됩니다. |
| `messageIdPrefix`  | `string`                   | `"msg"`                      | 만들어지는 메시지 ID 의 접두사입니다.                    |
| `toolCallIdPrefix` | `string`                   | `"call"`                     | 만들어지는 도구 호출 ID 의 접두사입니다.                 |
| `now`              | `Date \| string`           | `"2026-01-01T00:00:00.000Z"` | 만들어지는 `createdAt` 값에 쓸 고정 시각입니다.          |

`messages` 에 이미 있는 ID 는 비워 두므로, 새로 만들어지는 ID 는 그 뒤 번호부터
이어집니다.

### `TanStackChat`

내용을 더하는 메서드는 모두 같은 채팅을 돌려주므로 이어서 부를 수 있습니다.

| Method                        | Returns                    | Description                                                     |
| ----------------------------- | -------------------------- | --------------------------------------------------------------- |
| `user(text?, options?)`       | `TanStackChat`             | 글과, 원한다면 파일까지 담은 사용자 메시지를 더합니다.          |
| `assistant(input?, options?)` | `TanStackChat`             | 글이나 조각, 또는 writer 콜백으로 어시스턴트 메시지를 더합니다. |
| `sleep(delayMs)`              | `TanStackChat`             | 다음 어시스턴트 응답이 시작하기 전에 기다립니다.                |
| `error(errorText?)`           | `TanStackChat`             | `RUN_ERROR` 를 내는 어시스턴트 응답을 더합니다.                 |
| `get(count?)`                 | `UIMessage[]`              | 대화 처음부터의 메시지를 복제해 돌려줍니다.                     |
| `next(messages)`              | `UIMessage \| null`        | 주어진 기록 다음에 올, 미리 적어 둔 사용자 메시지를 돌려줍니다. |
| `transport(options?)`         | `ConnectConnectionAdapter` | `useChat` 이 쓸 연결을 만듭니다.                                |

`user()` 나 `assistant()` 를 내용 없이 부르면 `"Summarize the uploaded receipt."` 가
쓰입니다. `error()` 를 메시지 없이 부르면 `"An error occurred."` 가 쓰입니다.
`get(count)` 는 `count` 가 음수이거나 정수가 아니면 예외를 던집니다.

#### `user()` Options

| Option     | Type                      | Description                                     |
| ---------- | ------------------------- | ----------------------------------------------- |
| `id`       | `string`                  | 메시지 ID 를 직접 지정합니다.                   |
| `metadata` | `TanStackMessageMetadata` | 메시지의 `createdAt` 시각을 지정합니다.         |
| `files`    | `FilePayload[]`           | 사용자 텍스트 조각 뒤에 미디어 조각을 붙입니다. |

사용자 파일은 이런 모양입니다.

```ts
type FilePayload = {
  type?: "file"
  mediaType: string
  url: string
  filename?: string
  providerMetadata?: Record<string, unknown>
}
```

TanStack 미디어 조각은 주소와 미디어 타입을 지킵니다. 다만 그 메시지 구조에는
`filename` 이나 `providerMetadata` 가 남지 않습니다.

#### `assistant()` Input

| Input                  | Result                                                                 |
| ---------------------- | ---------------------------------------------------------------------- |
| `string`               | One text part that streams word by word.                               |
| `MessagePart[]`        | Static TanStack parts in their existing order.                         |
| `({ writer }) => void` | A synchronous callback for scripting parts, tools, errors, and timing. |

#### `assistant()` Options

| Option     | Type                      | Description                             |
| ---------- | ------------------------- | --------------------------------------- |
| `id`       | `string`                  | 메시지 ID 를 직접 지정합니다.           |
| `metadata` | `TanStackMessageMetadata` | 메시지의 `createdAt` 시각을 지정합니다. |

#### `transport()` Options

| Option     | Type                                                        | Default | Description                                                                       |
| ---------- | ----------------------------------------------------------- | ------- | --------------------------------------------------------------------------------- |
| `delayMs`  | `number`                                                    | `50`    | 글자와 추론이 조금씩 나올 때의 간격입니다. `0` 이나 `undefined` 를 주면 없앱니다. |
| `fallback` | `string \| MessagePart[] \| ({ writer, messages }) => void` | None    | 미리 적어 둔 어시스턴트 응답이 남지 않았을 때 쓰는 응답입니다.                    |

맞추기·fallback·오류·AG-UI 동작은 [Transport](#transport)를 보세요.

### Writer

writer 는 `assistant(({ writer }) => {})` 안과 fallback 콜백 안에서 쓸 수 있습니다.

| Method                       | Description                                                    |
| ---------------------------- | -------------------------------------------------------------- |
| `text(text?, options?)`      | 흘려보낼 글을 더합니다.                                        |
| `reasoning(text?, options?)` | `thinking` 조각이 될 추론을 더합니다.                          |
| `tool(name, options?)`       | 타입이 붙은 도구 호출을 더하고 그 수명 주기 핸들을 돌려줍니다. |
| `sleep(delayMs)`             | 다음 writer 이벤트 전에 잠시 멈춥니다.                         |
| `error(errorText?)`          | `RUN_ERROR` 를 내고 `RUN_FINISHED` 없이 끝냅니다.              |

`text()` 를 내용 없이 부르면 `"Summarize the uploaded receipt."` 가 쓰입니다.
`reasoning()` 을 내용 없이 부르면
`"I need to inspect the available context before answering."` 가 쓰입니다.
`error()` 를 메시지 없이 부르면 `"An error occurred."` 가 쓰입니다.

#### Text and Reasoning Options

| Option    | Type                    | Default    | Description                                                |
| --------- | ----------------------- | ---------- | ---------------------------------------------------------- |
| `delayMs` | `number`                | Connection | 이 값에 한해 연결의 간격을 바꿉니다.                       |
| `mode`    | `"stream" \| "instant"` | `"stream"` | 낱말 단위로 흘려보낼지, 값 전체를 한 번에 보낼지 정합니다. |

#### Tool Options

| Option       | Type                    | Description                           |
| ------------ | ----------------------- | ------------------------------------- |
| `toolCallId` | `string`                | 도구 호출 ID 를 직접 지정합니다.      |
| `input`      | `TOOLS[NAME]["input"]`  | 타입이 붙은 도구 입력을 지정합니다.   |
| `output`     | `TOOLS[NAME]["output"]` | 타입이 붙은 출력으로 곧바로 끝냅니다. |
| `errorText`  | `string`                | 오류로 곧바로 끝냅니다.               |

`tool()` 은 `sleep(delayMs)`·`output(value)`·`error(errorText?)` 를 가진 핸들을
돌려줍니다. 도구의 입력과 결과 사이에 무언가를 끼워 넣어야 할 때 쓰세요.
`tool.error()` 를 메시지 없이 부르면 `"Tool call failed."` 가 쓰입니다.

### Types

| Export                    | Description                                                      |
| ------------------------- | ---------------------------------------------------------------- |
| `TanStackChat`            | `createChat()` 이 돌려주는, 타입이 붙은 연쇄 호출용 채팅입니다.  |
| `CreateChatOptions`       | `createChat()` 이 받는 옵션입니다.                               |
| `TanStackMessageMetadata` | 지원하는 `{ createdAt? }` 메시지 메타데이터입니다.               |
| `TanStackToolHandle`      | `writer.tool()` 이 돌려주는 수명 주기 핸들입니다.                |
| `TanStackWriter`          | 어시스턴트 콜백과 fallback 콜백 안에서 쓸 수 있는 writer 입니다. |
