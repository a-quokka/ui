## Approach

이 폼은 스키마를 먼저 두는 헤드리스 방식으로 Formisch 를 씁니다. `<Field />` 로 만들기 때문에 **마크업과 스타일을 온전히 마음대로** 할 수 있습니다.

- 폼 상태는 Formisch 의 `useForm` 훅으로 관리합니다.
- `<Form />` 이 네이티브 `<form>` 을 감싸 제출을 처리합니다.
- 제어되는 입력에는 render-prop 방식의 `<Field />` 를 씁니다.
- 검증은 [Valibot](https://valibot.dev) 으로 합니다.
- 필드 경로는 스키마에서 추론돼 타입이 안전합니다.

## Form Methods

Formisch 는 폼 동작을 객체의 메서드가 아니라 **최상위 함수**로 제공합니다. 필요한 것만 가져다 쓰세요.

```ts
import { getInput, insert, reset, submit } from "@formisch/react"
```

모든 함수가 같은 형태입니다. **첫 인자는 언제나 폼 스토어**, **둘째 인자는 필요할 때 설정 객체**입니다.

```ts
// Read a field value
const email = getInput(form, { path: ["email"] })

// Reset the form with new initial values
reset(form, { initialInput: { email: "", password: "" } })

// Move an item in a field array
move(form, { path: ["items"], from: 0, to: 3 })
```

그래서 API 가 유연하면서도 일관됩니다. 이 문서 전반에서 상태 읽기(`getInput`·`getErrors`), 상태 쓰기(`setInput`·`setErrors`), 폼 제어(`submit`·`validate`·`focus`), 배열 조작(`insert`·`remove`·`move`·`swap`·`replace`) 모두 같은 `(form, config)` 모양으로 나옵니다. 자세한 내용은 [전체 메서드 레퍼런스](https://formisch.dev/react/guides/form-methods)를 보세요.

## Anatomy

Formisch 의 `<Field />` 와 shadcn 의 `<Field />` 를 함께 쓴 기본 예시입니다.

```tsx showLineNumbers {3-21}
<Form of={form} onSubmit={handleSubmit}>
  <FieldGroup>
    <FormischField of={form} path={["title"]}>
      {(field) => (
        <Field data-invalid={field.errors !== null}>
          <FieldLabel htmlFor="form-title">Bug Title</FieldLabel>
          <Input
            {...field.props}
            id="form-title"
            value={field.input}
            aria-invalid={field.errors !== null}
            placeholder="Login button not working on mobile"
            autoComplete="off"
          />
          <FieldDescription>
            Provide a concise title for your bug report.
          </FieldDescription>
          {field.errors && (
            <FieldError errors={field.errors.map((message) => ({ message }))} />
          )}
        </Field>
      )}
    </FormischField>
  </FieldGroup>
</Form>
```

## Form

### Create a form schema

먼저 Valibot 스키마로 폼의 모양을 정의합니다. Formisch 는 이 스키마에서 입력·출력 타입을 모두 추론합니다.

```tsx showLineNumbers title="form.tsx"
import * as v from "valibot"

const FormSchema = v.object({
  title: v.pipe(
    v.string(),
    v.minLength(5, "Bug title must be at least 5 characters."),
    v.maxLength(32, "Bug title must be at most 32 characters.")
  ),
  description: v.pipe(
    v.string(),
    v.minLength(20, "Description must be at least 20 characters."),
    v.maxLength(100, "Description must be at most 100 characters.")
  ),
})
```

### Set up the form

다음으로 Formisch 의 `useForm` 훅으로 폼 인스턴스를 만듭니다. 스키마를 `useForm` 에 바로 넘기며 resolver 단계는 없습니다.

```tsx showLineNumbers title="form.tsx" {1-2,21-25}
import { Form, Field as FormischField, useForm } from "@formisch/react"
import type { SubmitHandler } from "@formisch/react"
import * as v from "valibot"

const FormSchema = v.object({
  title: v.pipe(
    v.string(),
    v.minLength(5, "Bug title must be at least 5 characters."),
    v.maxLength(32, "Bug title must be at most 32 characters.")
  ),
  description: v.pipe(
    v.string(),
    v.minLength(20, "Description must be at least 20 characters."),
    v.maxLength(100, "Description must be at most 100 characters.")
  ),
})

export function BugReportForm() {
  const form = useForm({
    schema: FormSchema,
    initialInput: {
      title: "",
      description: "",
    },
  })

  const handleSubmit: SubmitHandler<typeof FormSchema> = (output) => {
    // Do something with the validated form values.
    console.log(output)
  }

  return (
    <Form of={form} onSubmit={handleSubmit}>
      {/* ... */}
      {/* Build the form here */}
      {/* ... */}
    </Form>
  )
}
```

`<Form />` 은 네이티브 `<form>` 을 감쌉니다. `event.preventDefault()` 를 부르고 검증을 돌린 뒤 데이터가 올바를 때만 `onSubmit` 을 호출합니다. 받는 `output` 은 스키마에서 추론된 타입을 그대로 가집니다.

여기까지입니다. 이제 클라이언트 검증이 붙은, 접근성을 갖춘 폼이 생겼습니다.

폼을 제출하면 검증된 데이터와 함께 `handleSubmit` 이 불립니다. 데이터가 올바르지 않으면 Formisch 가 각 필드의 `field.errors` 를 채우고 화면에 표시됩니다.

## Validation

### Client-side Validation

Formisch 는 `useForm` 에 넘긴 Valibot 스키마로 데이터를 검증합니다. resolver 는 없고, 스키마 하나가 런타임 검증과 정적 타입 모두의 기준이 됩니다.

```tsx showLineNumbers title="form.tsx" {1,3-6,11}
import { useForm } from "@formisch/react"

const FormSchema = v.object({
  title: v.string(),
  description: v.optional(v.string()),
})

export function ExampleForm() {
  const form = useForm({
    schema: FormSchema,
    initialInput: {
      title: "",
      description: "",
    },
  })
}
```

### Validation Modes

Formisch 는 **첫 검증**과 **그 이후 검증**을 나눠 다룹니다. `useForm` 의 `validate` 와 `revalidate` 옵션으로 정합니다.

```tsx showLineNumbers title="form.tsx" {3-4}
const form = useForm({
  schema: FormSchema,
  validate: "blur",
  revalidate: "input",
})
```

| Option       | Value       | Description                                              |
| ------------ | ----------- | -------------------------------------------------------- |
| `validate`   | `"submit"`  | 폼을 제출할 때 검증합니다(기본값).                       |
| `validate`   | `"blur"`    | 필드에서 포커스가 빠질 때 검증합니다.                    |
| `validate`   | `"input"`   | 값이 바뀔 때마다 검증합니다.                             |
| `validate`   | `"initial"` | 폼을 만들자마자 검증합니다.                              |
| `revalidate` | `"input"`   | 첫 검증 뒤에는 값이 바뀔 때마다 다시 검증합니다(기본값). |
| `revalidate` | `"blur"`    | 첫 검증 뒤에는 포커스가 빠질 때 다시 검증합니다.         |
| `revalidate` | `"submit"`  | 제출할 때만 다시 검증합니다.                             |

## Displaying Errors

오류는 `<FieldError />` 로 입력 옆에 보여 줍니다. Formisch 는 오류를 문자열 배열로 돌려주므로 `<FieldError />` 가 기대하는 모양으로 옮겨 주세요. 스타일과 접근성을 위해 이렇게 하세요.

- `<Field />` 에 `data-invalid` prop 을 붙입니다.
- `<Input />`·`<SelectTrigger />`·`<Checkbox />` 같은 입력에는 `aria-invalid` prop 을 붙입니다.

```tsx showLineNumbers title="form.tsx" {3,10,12-14}
<FormischField of={form} path={["email"]}>
  {(field) => (
    <Field data-invalid={field.errors !== null}>
      <FieldLabel htmlFor="form-email">Email</FieldLabel>
      <Input
        {...field.props}
        id="form-email"
        value={field.input}
        type="email"
        aria-invalid={field.errors !== null}
      />
      {field.errors && (
        <FieldError errors={field.errors.map((message) => ({ message }))} />
      )}
    </Field>
  )}
</FormischField>
```

## Working with Different Field Types

Formisch 는 필드를 요소에 연결하는 방법을 두 가지 제공합니다.

- **네이티브 HTML 요소**(`<Input />`·`<Textarea />` 등) — `field.props` 를 펼쳐 넣고 `value={field.input}` 을 줍니다. `name`·`ref`·`onChange`·`onBlur`·`onFocus` 는 Formisch 가 연결해 줍니다.
- **컴포넌트 라이브러리 입력**(Radix 기반 `<Select />`·`<Checkbox />`·`<RadioGroup />`·`<Switch />` 등) — 값은 `field.input` 에서 읽고 바꿀 때는 `field.onChange(value)` 를 부릅니다.

### Input

- 입력 필드에는 `field.props` 를 펼쳐 넣고 `value={field.input}` 을 줍니다.
- 오류를 보이려면 `<Input />` 에 `aria-invalid` 를, `<Field />` 에 `data-invalid` 를 붙입니다.

- 체크박스 배열은 `field.input` 을 읽고 `onCheckedChange` 에서 `field.onChange` 로 갱신합니다.

<FormischField of={form} path={["tasks"]}>
  {(field) => (
    <FieldSet>
      <FieldLegend variant="label">Tasks</FieldLegend>
      <FieldDescription>
        Get notified when tasks you&apos;ve created have updates.
      </FieldDescription>
      <FieldGroup data-slot="checkbox-group">
        {tasks.map((task) => (
          <Field
            key={task.id}
            orientation="horizontal"
            data-invalid={field.errors !== null}
          >
            <Checkbox
              id={`form-checkbox-${task.id}`}
              aria-invalid={field.errors !== null}
              checked={field.input?.includes(task.id) ?? false}
              onCheckedChange={(checked) => {
                const current = field.input ?? []
                field.onChange(
                  checked === true
                    ? [...current, task.id]
                    : current.filter((value) => value !== task.id)
                )
              }}
            />
            <FieldLabel
              htmlFor={`form-checkbox-${task.id}`}
              className="font-normal"
            >
              {task.label}
            </FieldLabel>
          </Field>
        ))}
      </FieldGroup>
      {field.errors && (
        <FieldError errors={field.errors.map((message) => ({ message }))} />
      )}
    </FieldSet>
  )}
</FormischField>

## Resetting the Form

Formisch 는 최상위 `reset` 함수를 제공합니다. 폼 스토어를 넘기면 처음 값으로 되돌립니다.

```tsx showLineNumbers
<Button type="button" variant="outline" onClick={() => reset(form)}>
  Reset
</Button>
```

새 초기값으로 되돌리거나, 사용자가 입력한 값을 유지한 채 되돌릴 수도 있습니다.

```tsx showLineNumbers
// Reset to a fresh set of initial values
reset(form, { initialInput: { title: "", description: "" } })

// Sync the baseline to new server data, but keep the user's edits
reset(form, { initialInput: serverData, keepInput: true })
```

### Using FieldArray

`<FieldArray />` 도 `<Field />` 와 같은 render-prop 방식입니다. `items` 배열에는 항목마다 값이 바뀌지 않는 키가 들어 있으니 React `key` 로 쓰세요.

```tsx showLineNumbers title="form.tsx" {1,7-22}
import {
  Field as FormischField,
  FieldArray,
  insert,
  remove,
} from "@formisch/react"

export function ExampleForm() {
  // ... form config

  return (
    <FieldArray of={form} path={["emails"]}>
      {(fieldArray) => (
        <FieldGroup className="gap-4">
          {fieldArray.items.map((item, index) => (
            <FormischField
              key={item}
              of={form}
              path={["emails", index, "address"]}
            >
              {(field) => /* ... */}
            </FormischField>
          ))}
        </FieldGroup>
      )}
    </FieldArray>
  )
}
```

### Array Field Structure

배열 입력은 `<FieldLegend />` 와 `<FieldDescription />` 을 둔 `<FieldSet />` 으로 감쌉니다.

```tsx showLineNumbers title="form.tsx"
<FieldSet className="gap-4">
  <FieldLegend variant="label">Email Addresses</FieldLegend>
  <FieldDescription>
    Add up to 5 email addresses where we can contact you.
  </FieldDescription>
  <FieldGroup className="gap-4">{/* Array items go here */}</FieldGroup>
</FieldSet>
```

### Adding Items

`insert` 로 배열에 항목을 더합니다. 기본은 끝에 붙이고, `at` 으로 위치를 지정할 수도 있습니다.

```tsx showLineNumbers title="form.tsx"
<Button
  type="button"
  variant="outline"
  size="sm"
  onClick={() =>
    insert(form, { path: ["emails"], initialInput: { address: "" } })
  }
  disabled={fieldArray.items.length >= 5}
>
  Add Email Address
</Button>
```

### Removing Items

`remove` 에 `at` 을 주어 배열에서 항목을 뺍니다.

```tsx showLineNumbers title="form.tsx"
import { remove } from "@formisch/react"

{
  fieldArray.items.length > 1 && (
    <InputGroupAddon align="inline-end">
      <InputGroupButton
        type="button"
        variant="ghost"
        size="icon-xs"
        onClick={() => remove(form, { path: ["emails"], at: index })}
        aria-label={`Remove email ${index + 1}`}
      >
        <XIcon />
      </InputGroupButton>
    </InputGroupAddon>
  )
}
```

순서를 바꾸거나 교체하는 `move`·`swap`·`replace` 도 있습니다. 모두 같은 `(form, config)` 형태입니다.

### Array Validation

배열 필드에 조건을 걸려면 Valibot 의 `array` 와 파이프라인 검증기를 쓰세요.

```tsx showLineNumbers title="form.tsx"
const FormSchema = v.object({
  emails: v.pipe(
    v.array(
      v.object({
        address: v.pipe(
          v.string(),
          v.nonEmpty("Enter an email address."),
          v.email("Enter a valid email address.")
        ),
      })
    ),
    v.minLength(1, "Add at least one email address."),
    v.maxLength(5, "You can add up to 5 email addresses.")
  ),
})
```
