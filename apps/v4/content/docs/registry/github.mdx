이제 **어떤 GitHub 저장소든 레지스트리로 만들 수 있습니다.**

저장소 루트에 `registry.json` 을 두고 나누고 싶은 파일을 적어 두면, 사용자가
`shadcn` CLI 로 설치할 수 있습니다.

```bash
npx shadcn@latest add <username>/<repo>/<item>
```

레지스트리 서버를 세우거나 생성된 JSON 을 배포할 필요가 없습니다. **GitHub 저장소 자체가 원본 레지스트리가 됩니다.**

## Distribute Anything

레지스트리 항목은 **컴포넌트나 React 코드에 한정되지 않습니다.** 소스 파일,
설정, 문서, 템플릿, 워크플로, 규칙, 프로젝트 관례 등 저장소의 어떤 파일이든
담을 수 있습니다.

## When to use GitHub

GitHub 레지스트리는 이럴 때 씁니다.

- 다시 쓸 코드가 이미 GitHub 저장소에 있을 때
- 사용자가 `owner/repo/item` 으로 바로 설치하게 하고 싶을 때
- 같은 저장소의 설정 파일·규칙·문서·템플릿·유틸리티 같은 파일을 함께
  나누고 싶을 때
- 별도 레지스트리 서버나 요청 인증이 필요 없을 때

## Requirements

GitHub 레지스트리는 아래를 만족해야 합니다.

- `github.com` 저장소여야 합니다.
- 저장소 루트에 `registry.json` 이 있어야 합니다.
- `registry.json` 과 `registry-item.json` 스키마를 지켜야 합니다.
- 참조하는 소스 파일이 실제로 저장소에 있어야 합니다.

공개 저장소는 설정 없이 그대로 동작합니다. 비공개 저장소는 GitHub 자격 증명이
있으면 됩니다. [비공개 저장소](#private-repositories)를 보세요.

GitHub Enterprise 호스트는 GitHub 주소로 지원하지 않습니다. 요청 인증이 필요한
레지스트리 서버라면 [네임스페이스](/docs/registry/namespace)와
[인증](/docs/registry/authentication)을 쓰세요.

## Step 1: Add registry.json

이미 있는 저장소가 이렇다고 하면,

```txt
.
├── ...
├── .editorconfig
├── AGENTS.md
└── docs
    └── conventions.md
```

저장소 루트에 `registry.json` 을 둡니다.

```txt
.
├── ...
├── registry.json
├── .editorconfig
├── AGENTS.md
└── docs
    └── conventions.md
```

나누고 싶은 항목을 정의합니다.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "project-conventions",
      "type": "registry:item",
      "title": "Project Conventions",
      "description": "Shared project conventions, editor settings and agent instructions.",
      "files": [
        {
          "path": "AGENTS.md",
          "type": "registry:file",
          "target": "~/AGENTS.md"
        },
        {
          "path": ".editorconfig",
          "type": "registry:file",
          "target": "~/.editorconfig"
        },
        {
          "path": "docs/conventions.md",
          "type": "registry:file",
          "target": "~/docs/conventions.md"
        }
      ]
    }
  ]
}
```

파일을 커밋하고 푸시합니다.

```bash
git add registry.json
```

```bash
git commit -m "add registry"
```

```bash
git push
```

이제 사용자가 GitHub 에서 그 항목을 설치할 수 있습니다.

```bash
npx shadcn@latest add acme/toolkit/project-conventions
```

## Step 2: Distribute any file

항목 하나가 파일 하나를 설치할 수도, 여러 개를 설치할 수도 있습니다. 함께
묶이는 파일은 `files` 배열에 적으세요.

예를 들어 테스트 설정 항목이 Vitest 설정, 셋업 파일, 짧은 팀 안내문을 함께
설치할 수 있습니다.

```txt
registry.json
config
└── vitest.config.ts
docs
└── testing.md
test
└── setup.ts
```

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "vitest-setup",
      "type": "registry:item",
      "title": "Vitest Setup",
      "description": "A Vitest setup with project defaults and docs.",
      "files": [
        {
          "path": "config/vitest.config.ts",
          "type": "registry:file",
          "target": "~/vitest.config.ts"
        },
        {
          "path": "test/setup.ts",
          "type": "registry:file",
          "target": "~/test/setup.ts"
        },
        {
          "path": "docs/testing.md",
          "type": "registry:file",
          "target": "~/docs/testing.md"
        }
      ]
    }
  ]
}
```

설치 방법은 똑같습니다.

```bash
npx shadcn@latest add acme/toolkit/vitest-setup
```

사용자 프로젝트의 특정 위치에 파일을 써야 한다면 `target` 을 쓰세요.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "editorconfig",
      "type": "registry:file",
      "files": [
        {
          "path": "config/.editorconfig",
          "type": "registry:file",
          "target": "~/.editorconfig"
        }
      ]
    }
  ]
}
```

```bash
npx shadcn@latest add acme/toolkit/editorconfig
```

## Step 3: Validate the registry

레지스트리를 나누기 전에 CLI 로 검증하세요.

```bash
npx shadcn@latest registry validate acme/toolkit
```

이 명령은 루트 `registry.json` 을 읽고 include 를 풀고 항목을 검증한 뒤,
참조하는 파일이 실제로 있는지 확인합니다.

브랜치·태그·커밋 SHA 를 지정해 검증할 수도 있습니다.

```bash
npx shadcn@latest registry validate acme/toolkit#v1.0.0
```

## Step 4: List and search items

`list` 로 저장소 레지스트리의 모든 항목을 봅니다.

```bash
npx shadcn@latest list acme/toolkit
```

`search` 로 카탈로그를 거릅니다.

```bash
npx shadcn@latest search acme/toolkit --query conventions
```

`view` 로 항목 하나의 내용을 들여다봅니다.

```bash
npx shadcn@latest view acme/toolkit/project-conventions
```

## Organize with include

저장소가 크다면 항목 정의를 그 항목이 설명하는 소스 파일 가까이에 두세요.

```txt
registry.json
config
├── prettier.config.mjs
└── registry.json
rules
├── agent.md
└── registry.json
```

루트 `registry.json` 이 하위 레지스트리 파일들을 포함할 수 있습니다.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "include": ["config/registry.json", "rules/registry.json"]
}
```

포함된 레지스트리 파일은 그 디렉터리의 항목을 선언합니다.

```json title="rules/registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "items": [
    {
      "name": "agent-rules",
      "type": "registry:file",
      "files": [
        {
          "path": "agent.md",
          "type": "registry:file",
          "target": "~/AGENTS.md"
        }
      ]
    }
  ]
}
```

`include` 를 쓸 때 파일 경로는 그 항목을 선언한 `registry.json` 기준입니다.

```bash
npx shadcn@latest add acme/toolkit/project-conventions
```

## Registry dependencies

항목이 다른 항목에 기댄다면 `registryDependencies` 를 쓰세요.

### Same repository dependencies

같은 GitHub 저장소 안의 의존성이라면 전체 GitHub 항목 주소를 쓰세요.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "project-setup",
      "type": "registry:item",
      "registryDependencies": [
        "acme/toolkit/agent-rules",
        "acme/toolkit/prettier-config",
        "acme/toolkit/tsconfig"
      ],
      "files": [
        {
          "path": "docs/project-setup.md",
          "type": "registry:file",
          "target": "~/docs/project-setup.md"
        }
      ]
    }
  ]
}
```

문서 항목이 같은 저장소의 템플릿 항목에 기댈 수 있습니다.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "contributing-guide",
      "type": "registry:item",
      "registryDependencies": ["acme/toolkit/readme-template"],
      "files": [
        {
          "path": "docs/contributing.md",
          "type": "registry:file",
          "target": "~/docs/contributing.md"
        }
      ]
    }
  ]
}
```

CI 설정 항목이, 사용자가 따로 설치할 수도 있는 포매팅·테스트 기본값에 기댈 수
있습니다.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "ci-setup",
      "type": "registry:item",
      "registryDependencies": [
        "acme/toolkit/prettier-config",
        "acme/toolkit/vitest-setup"
      ],
      "files": [
        {
          "path": ".github/workflows/ci.yml",
          "type": "registry:file",
          "target": "~/.github/workflows/ci.yml"
        }
      ]
    }
  ]
}
```

### External registry dependencies

다른 레지스트리에 기댈 수도 있습니다. 그 의존성을 가진 레지스트리의 전체 항목
주소를 쓰세요.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "workspace-setup",
      "type": "registry:item",
      "registryDependencies": [
        "@acme/tsconfig",
        "contoso/devtools/prettier-config"
      ],
      "files": [
        {
          "path": "docs/workspace.md",
          "type": "registry:file",
          "target": "~/docs/workspace.md"
        }
      ]
    }
  ]
}
```

### Dependency refs

ref 는 의존성에 물려받지 않습니다. 의존성을 고정하려면 그 의존성에도 ref 를
적으세요.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme-toolkit",
  "homepage": "https://github.com/acme/toolkit",
  "items": [
    {
      "name": "project-setup",
      "type": "registry:item",
      "registryDependencies": [
        "acme/toolkit/agent-rules#v1.0.0",
        "acme/toolkit/tsconfig#c0ffee254729296a45d6691db565cf707a3fef5d"
      ],
      "files": [
        {
          "path": "docs/project-setup.md",
          "type": "registry:file",
          "target": "~/docs/project-setup.md"
        }
      ]
    }
  ]
}
```

## Useful commands

GitHub 레지스트리의 모든 항목을 나열합니다.

```bash
npx shadcn@latest list acme/toolkit
```

GitHub 레지스트리를 검색합니다.

```bash
npx shadcn@latest search acme/toolkit -q conventions
```

GitHub 레지스트리를 검증합니다.

```bash
npx shadcn@latest registry validate acme/toolkit
```

GitHub 레지스트리에서 항목을 설치합니다.

```bash
npx shadcn@latest add acme/toolkit/project-conventions
```

GitHub 레지스트리의 항목을 봅니다.

```bash
npx shadcn@latest view acme/toolkit/project-conventions
```

항목 이름에 `/` 가 들어간 항목을 설치합니다.

```bash
npx shadcn@latest add acme/toolkit/rules/agent
```

<Callout>
  GitHub 항목 주소에서 앞의 두 조각은 GitHub 소유자와 저장소입니다. 나머지는
  파일 경로가 아니라 항목 이름입니다. `.json` 으로 끝나는 주소는 파일 경로로
  봅니다.
</Callout>

태그에서 설치합니다.

```bash
npx shadcn@latest add acme/toolkit/project-conventions#v1.0.0
```

전체 커밋 SHA 에서 설치합니다.

```bash
npx shadcn@latest add acme/toolkit/project-conventions#c0ffee254729296a45d6691db565cf707a3fef5d
```

## Refs

브랜치·태그·커밋 SHA 에서 설치하려면 `#ref` 를 씁니다.

```bash
npx shadcn@latest add acme/toolkit/project-conventions#main
```

ref 에는 슬래시가 들어갈 수 있습니다.

```bash
npx shadcn@latest add acme/toolkit/project-conventions#feature/conventions
```

ref 를 주지 않으면 CLI 는 저장소의 기본 브랜치를 씁니다.

CLI 는 파일을 읽기 전에 Git 으로 브랜치·태그·짧은 ref 를 커밋 SHA 로 풀어
냅니다. 40자짜리 전체 SHA 는 그대로 쓰므로 Git 이 필요 없습니다.

## Private repositories

비공개 `github.com` 저장소도 레지스트리로 쓸 수 있습니다. 서버를 세우거나
레지스트리 쪽에 설정할 것은 없습니다. 저장소를 읽을 수 있으면 CLI 도 설치할 수
있습니다.

### Use the GitHub CLI

로컬에서 작업한다면 GitHub CLI 로 한 번 인증해 두세요.

```bash
gh auth login
```

그다음은 다른 GitHub 레지스트리와 똑같이 설치하면 됩니다.

```bash
npx shadcn@latest add acme/private-toolkit/project-conventions
```

저장소가 공개로 읽히지 않으면 CLI 는 저장된 자격 증명으로 `gh` 를 통해 읽습니다.
토큰은 GitHub CLI 안에만 있고 shadcn 프로세스로 넘어오지 않습니다.

명령이 처음으로 자격 증명을 쓸 때 안내를 출력합니다.

```txt
✔ Using gh credentials.
```

### Use a token in CI

GitHub CLI 가 없다면 `GH_TOKEN` 이나 `GITHUB_TOKEN` 을 지정하세요.

```bash
GH_TOKEN=github_pat_xxx npx shadcn@latest add acme/private-toolkit/project-conventions
```

- `GH_TOKEN` 이 `GITHUB_TOKEN` 보다 우선합니다.
- 저장소 범위로 좁힌 fine-grained 개인 접근 토큰에 **Contents: Read-only** 권한만
  주는 것을 권합니다.
- 토큰이 있으면 GitHub CLI 대신 그것을 쓰고, `api.github.com` 으로만 보냅니다.

<Callout>
  GitHub Actions 의 기본 `GITHUB_TOKEN` 은 보통 그 워크플로가 속한 저장소만 읽을
  수 있습니다. 다른 저장소의 비공개 레지스트리에서 설치하려면 fine-grained 개인
  접근 토큰이나 GitHub App 설치 토큰을 쓰세요.
</Callout>

### How it works

- 공개 저장소는 항상 익명으로 읽습니다. 자격 증명을 쓰지 않고 GitHub CLI 도
  부르지 않습니다.
- CLI 는 익명 접근을 먼저 시도합니다. 루트 `registry.json` 이 공개로 읽히지
  않을 때만 자격 증명을 씁니다.
- ref 해석은 `git ls-remote` 를 먼저 돌립니다. `gh auth setup-git` 으로 설정한
  것처럼 이미 자격 증명 도우미가 있다면 Git 이 그것을 쓸 수 있습니다.
- 비공개 파일은 해석된 커밋 SHA 에 고정해 GitHub Contents API 로 읽습니다.
- GitHub 은 비공개 저장소와 없는 저장소에 같은 응답을 돌려줍니다. 자격 증명으로도
  읽지 못하면 CLI 는 둘 중 어느 쪽인지 알려 줄 수 없습니다.

### Limits

- 레지스트리 소스 파일은 하나당 5 MiB 까지입니다.
- GitHub Enterprise 호스트는 지원하지 않습니다. GitHub 주소는 항상
  `github.com` 기준으로 풀립니다.
- 소스 파일에 심볼릭 링크는 피하세요. 익명으로 읽으면 링크가 가리키는 경로가
  글자로 돌아오고, 인증해서 Contents API 로 읽으면 대상 파일의 내용이
  돌아옵니다.

## Review before installing

GitHub 레지스트리 항목은 GitHub 저장소의 코드와 프로젝트 파일을 설치합니다.
GitHub 항목 주소는 다른 서드파티 의존성과 똑같이 다루세요.

직접 관리하지 않는 곳에서 설치하기 전에 이렇게 확인하세요.

- 저장소와 루트 `registry.json` 을 읽어 봅니다.
- 항목 정의를 읽습니다. 특히 `files`·`target`·`dependencies`·
  `devDependencies`·`registryDependencies`·`envVars` 를 봅니다.
- 외부 레지스트리 의존성이 있는지 확인합니다. 다른 레지스트리의 파일을 설치할
  수 있습니다.
- 공개하는 설치 명령에는 ref 를 고정하는 편이 낫습니다. 40자짜리 전체 커밋 SHA 가
  가장 재현하기 좋습니다.
- 설치 전에 `shadcn view acme/toolkit/project-conventions` 로 풀어낸 항목 내용을
  확인합니다.
- 확인에 도움이 필요하면 `shadcn view` 출력을 에이전트나 검토 도구에 넘기세요.
- `shadcn add acme/toolkit/project-conventions --dry-run` 으로 파일을 쓰지 않고
  설치 결과를 미리 봅니다.
- `shadcn add` 에 `--diff` 나 `--view` 를 붙이면 적용 전에 파일 변경이나 내용을
  확인할 수 있습니다.
