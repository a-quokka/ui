직접 레지스트리를 만드는 과정을 살펴봅니다. 나누고 싶은 컴포넌트·훅·유틸리티 같은 파일이 이미 있는 프로젝트를 전제로 합니다.

**공개 GitHub 저장소가 이미 있다면 루트에 `registry.json` 을 두는 것만으로
레지스트리가 됩니다.** 자세한 내용은 [GitHub 레지스트리](/docs/registry/github)를
보세요.

새로 시작한다면 [레지스트리 템플릿](https://github.com/shadcn-ui/registry-template)에서 출발하면 됩니다. 설정은 이미 돼 있습니다.

## Requirements

레지스트리는 원하는 대로 설계하고 배포하면 됩니다. 지켜야 할 것은 하나, 카탈로그와 항목이 [registry 스키마 규격](/docs/registry/registry-json)과 [registry-item 스키마 규격](/docs/registry/registry-item-json)을 따라야 한다는 것뿐입니다.

HTTP 로 JSON 을 내보낼 수만 있다면 Next.js·Vite·Vue·Svelte·PHP 등 무엇으로 만들어도 됩니다. 루트에 `registry.json` 을 둔 공개 GitHub 저장소여도 됩니다.

예시가 필요하다면 [템플릿 프로젝트](https://github.com/shadcn-ui/registry-template)에서 시작할 수 있습니다.

## registry.json

`registry.json` 은 레지스트리의 입구입니다. 이름과 홈페이지가 들어 있고 레지스트리에 있는 항목을 모두 정의합니다.

이 파일(또는 JSON 응답)이 레지스트리 엔드포인트 루트에 있어야 합니다. 엔드포인트는 레지스트리를 올려 둔 주소입니다.

`registry.json` 예시입니다.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme",
  "homepage": "https://acme.com",
  "items": [
    {
      "name": "button",
      "type": "registry:ui",
      "title": "Button",
      "description": "A simple button component.",
      "files": [
        {
          "path": "components/ui/button.tsx",
          "type": "registry:ui"
        }
      ]
    }
  ]
}
```

## Structure your registry

원본 레지스트리는 두 가지 방식으로 짤 수 있습니다.

- 루트 `registry.json` 하나에 모든 항목을 정의합니다.
- 루트 `registry.json` 에서 `include` 로 여러 `registry.json` 을 엮습니다.

### Option A: Single registry.json

프로젝트 루트에 `registry.json` 을 만들고 `items` 배열에 항목을 모두 넣습니다. 가장 단순한 방법입니다.

```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme",
  "homepage": "https://acme.com",
  "items": [
    {
      "name": "button",
      "type": "registry:ui",
      "title": "Button",
      "description": "A simple button component.",
      "files": [
        {
          "path": "components/ui/button.tsx",
          "type": "registry:ui"
        }
      ]
    },
    {
      "name": "hello-world",
      "type": "registry:block",
      "title": "Hello World",
      "description": "A simple hello world component.",
      "registryDependencies": ["button"],
      "files": [
        {
          "path": "registry/default/hello-world/hello-world.tsx",
          "type": "registry:component"
        }
      ]
    }
  ]
}
```

이 `registry.json` 은 [registry 스키마 규격](/docs/registry/registry-json)을 따라야 합니다.

### Option B: Using include

레지스트리가 크다면 `include` 로 여러 `registry.json` 을 엮어 구성할 수
있습니다.

```txt
registry.json
components
└── ui
    ├── button.tsx
    ├── input.tsx
    └── registry.json
hooks
├── registry.json
├── use-media-query.ts
└── use-toggle.ts
```

루트 `registry.json` 이 레지스트리 메타데이터를 정의하고 하위 레지스트리
파일들을 포함합니다.

{/* prettier-ignore */}
```json title="registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme",
  "homepage": "https://acme.com",
  "include": [
    "components/ui/registry.json",
    "hooks/registry.json"
  ]
}
```

포함되는 `registry.json` 은 조합용이라 `name` 과 `homepage` 를 생략해도 됩니다.
메타데이터는 루트 `registry.json` 만 정의하면 됩니다.

```json title="components/ui/registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "items": [
    {
      "name": "button",
      "type": "registry:ui",
      "files": [
        {
          "path": "button.tsx",
          "type": "registry:ui"
        }
      ]
    },
    {
      "name": "input",
      "type": "registry:ui",
      "files": [
        {
          "path": "input.tsx",
          "type": "registry:ui"
        }
      ]
    }
  ]
}
```

```json title="hooks/registry.json" showLineNumbers
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "items": [
    {
      "name": "use-toggle",
      "type": "registry:hook",
      "files": [
        {
          "path": "use-toggle.ts",
          "type": "registry:hook"
        }
      ]
    },
    {
      "name": "use-media-query",
      "type": "registry:hook",
      "files": [
        {
          "path": "use-media-query.ts",
          "type": "registry:hook"
        }
      ]
    }
  ]
}
```

`include` 를 쓸 때 파일 경로는 그 항목을 선언한 `registry.json` 기준입니다.

## Add an item

### Create a UI component

첫 항목을 넣습니다. 간단한 `<Button />` 컴포넌트 예시입니다.

```tsx title="components/ui/button.tsx" showLineNumbers
import * as React from "react"

export function Button(props: React.ComponentProps<"button">) {
  return (
    <button
      {...props}
      className="rounded-md bg-neutral-900 px-4 py-2 text-sm font-medium text-white"
    />
  )
}
```

<Callout className="mt-6">
  **참고:** 이 예시는 컴포넌트를 `components/ui` 에 둡니다. `registry.json` 에
  경로만 맞게 적으면 프로젝트 어디에 둬도 됩니다.
</Callout>

```txt
components
└── ui
    └── button.tsx
```

### Add the item to the registry

컴포넌트를 레지스트리에 넣으려면 `registry.json` 에 항목 정의를 추가합니다.
`include` 를 쓴다면 그 컴포넌트를 가진 쪽 `registry.json` 에 넣으세요. 예를 들어
UI 컴포넌트는 `components/ui/registry.json` 에 넣습니다.

```json title="registry.json" showLineNumbers {6-17}
{
  "$schema": "https://ui.shadcn.com/schema/registry.json",
  "name": "acme",
  "homepage": "https://acme.com",
  "items": [
    {
      "name": "button",
      "type": "registry:ui",
      "title": "Button",
      "description": "A simple button component.",
      "files": [
        {
          "path": "components/ui/button.tsx",
          "type": "registry:ui"
        }
      ]
    }
  ]
}
```

항목은 `name`·`type`·`title`·`description`·`files` 로 정의합니다.

파일마다 `path` 와 `type` 을 지정해야 합니다. 파일 하나짜리 레지스트리에서는 `path` 가 프로젝트 루트 기준이고, `include` 를 쓸 때는 그 항목을 선언한 `registry.json` 기준입니다. `type` 은 파일의 종류입니다.

항목 스키마와 파일 종류는 [registry item 스키마 문서](/docs/registry/registry-item-json)에서 더 볼 수 있습니다.

## Serve your registry

레지스트리는 정적 JSON 파일로 내보내도 되고 동적 라우트 핸들러로 내보내도 됩니다.

### Option A: Static JSON files

build 명령으로 정적 레지스트리 JSON 파일을 만듭니다.

```bash
npx shadcn@latest build
```

원본 레지스트리가 `include` 를 쓰면 `shadcn build` 가 포함된 레지스트리를 풀어
평평하게 만든 결과를 출력 디렉터리에 씁니다. 생성된 `registry.json` 에는
`include` 가 없습니다.

<Callout className="mt-6">
  **참고:** build 명령은 기본으로 `public/r` 에 JSON 파일을 만듭니다(예:
  `public/r/button.json`). `--output` 옵션으로 위치를 바꿀 수 있습니다. 자세한 내용은 [shadcn build 명령](/docs/cli#build)을 보세요.

</Callout>

Next.js 로 레지스트리를 운영한다면 `next` 서버를 띄워 파일을 내보내면 됩니다.
다른 프레임워크는 명령이 다를 수 있습니다.

```bash
npm run dev
```

이제 파일이 `http://localhost:3000/r/[NAME].json` 에서 열립니다(예: `http://localhost:3000/r/button.json`).

### Option B: Dynamic route handlers

요청이 올 때 원본 `registry.json` 에서 바로 JSON 을 만들어 내보내고 싶다면
`shadcn/registry` 의 로더 API 를 쓰세요.

`shadcn` 을 런타임 의존성으로 설치합니다.

```bash
npm install shadcn
```

카탈로그는 `loadRegistry` 로 내보냅니다.

```ts title="app/r/registry.json/route.ts" showLineNumbers
import { loadRegistry } from "shadcn/registry"

export async function GET() {
  try {
    const registry = await loadRegistry()

    return Response.json(registry)
  } catch (error) {
    console.error(error)

    return Response.json({ error: "Failed to load registry." }, { status: 500 })
  }
}
```

개별 항목은 `loadRegistryItem` 으로 내보냅니다.

```ts title="app/r/[name].json/route.ts" showLineNumbers
import { loadRegistryItem, RegistryItemNotFoundError } from "shadcn/registry"

export async function GET(
  _request: Request,
  context: {
    params: Promise<{
      name: string
    }>
  }
) {
  const { name } = await context.params

  try {
    const item = await loadRegistryItem(name)

    return Response.json(item)
  } catch (error) {
    if (error instanceof RegistryItemNotFoundError) {
      return Response.json(
        { error: `Registry item "${name}" was not found.` },
        { status: 404 }
      )
    }

    console.error(error)

    return Response.json(
      { error: "Failed to load registry item." },
      { status: 500 }
    )
  }
}
```

두 로더 모두 JSON 을 돌려주기 전에 `include` 를 풀어 줍니다. 그래서 라우트
핸들러는 `shadcn build` 없이도 같은 원본 구조를 그대로 쓸 수 있습니다.

`shadcn` CLI 는 **HTTP 콘텐츠 협상**을 지원합니다. 그래서 도메인 루트를 포함해 어떤 주소에 레지스트리를 두고도, 누가 요청했는지에 따라 다른 내용을 내보낼 수 있습니다.

주소 하나로 이런 것들을 내보낼 수 있습니다.

<ul>
  <li>
    <strong>HTML</strong> to browsers — a landing page, documentation, or
    marketing site.
  </li>
  <li>
    <strong>JSON</strong> to the <code>shadcn</code> CLI — an installable
    registry item.
  </li>
  <li>
    <strong>Markdown</strong> to AI agents and LLMs — a machine-readable version
    of your content.
  </li>
</ul>

클라이언트가 `Accept` 요청 헤더로 원하는 것을 알리면 서버가 무엇을 돌려줄지 정합니다.

#### Request headers

CLI 는 레지스트리에 요청할 때 아래 헤더를 보냅니다.

- **User-Agent**: `shadcn`
- **Accept**: `application/vnd.shadcn.v1+json, application/json;q=0.9`

#### Root hosting

서버에서 이 헤더를 확인하면 CLI 요청은 설치 가능한 레지스트리 항목으로, 브라우저 요청은 문서나 홈페이지로 보낼 수 있습니다.

아래 예시는 빌드된 항목이 `/r/index.json` 에 있다고 가정합니다. 실제 출력 위치에 맞게 고치세요.

Next.js 라면 `next.config.ts` 의 rewrite 로 표현합니다. 협상을 라우팅 계층에 두어 이 정적 rewrite 에 Proxy 함수를 쓰지 않아도 됩니다.

```typescript title="next.config.ts" showLineNumbers
import type { NextConfig } from "next"

const nextConfig: NextConfig = {
  async rewrites() {
    return {
      beforeFiles: [
        {
          source: "/",
          has: [
            {
              type: "header",
              key: "accept",
              value: "(.*)application/vnd\\.shadcn\\.v1\\+json(.*)",
            },
          ],
          destination: "/r/index.json",
        },
        {
          source: "/",
          has: [
            {
              type: "header",
              key: "user-agent",
              value: "shadcn",
            },
          ],
          destination: "/r/index.json",
        },
      ],
    }
  },
  async headers() {
    return [
      {
        source: "/",
        headers: [{ key: "Vary", value: "Accept, User-Agent" }],
      },
    ]
  },
}

export default nextConfig
```

Express.js 서버라면 이렇습니다.

```javascript title="server.js" showLineNumbers
app.get("/", (req, res) => {
  res.vary("Accept")
  res.vary("User-Agent")

  // Check if the client prefers the shadcn vendor type.
  if (req.accepts("application/vnd.shadcn.v1+json")) {
    return res.json(registryData)
  }

  // Optional: Secondary check for the User-Agent.
  if (req.get("User-Agent") === "shadcn") {
    return res.json(registryData)
  }

  // Otherwise, serve your documentation or homepage.
  res.send(htmlContent)
})
```

## Test your registry

레지스트리를 내보내기 시작했다면, 다른 개발자가 쓸 CLI 명령 그대로
확인해 보세요.

### Using URL

`list`·`search` 처럼 항목을 찾는 명령에는 카탈로그 주소를, `view`·`add` 처럼
특정 항목을 읽거나 설치하는 명령에는 항목 주소를 쓰세요.

#### List items

먼저 카탈로그가 발견되는지 확인합니다.

```bash
npx shadcn@latest list http://localhost:3000/r/registry.json
```

#### Search items

검색어로 레지스트리를 찾습니다.

```bash
npx shadcn@latest search http://localhost:3000/r/registry.json --query button
```

#### View an item

그다음 이름으로 항목 하나를 봅니다.

```bash
npx shadcn@latest view http://localhost:3000/r/button.json
```

#### Add an item

설치 흐름을 확인하려면 항목을 설치할 프로젝트에서 `add` 를 돌려 보세요.

```bash
npx shadcn@latest add http://localhost:3000/r/button.json
```

### Using namespace

#### Add the registry

네임스페이스로도 확인할 수 있습니다. `components.json` 이 있는 프로젝트에
레지스트리 주소 템플릿을 추가하세요.

```bash
npx shadcn@latest registry add @acme=http://localhost:3000/r/{name}.json
```

`{name}` 자리표시자는 항목 JSON 파일로 풀려야 합니다. 예를 들어 `@acme/button`
은 `http://localhost:3000/r/button.json` 이 됩니다. 카탈로그는 여전히
`http://localhost:3000/r/registry.json` 에서 따로 내보냅니다.

#### List items

그다음 레지스트리의 항목을 나열합니다.

```bash
npx shadcn@latest list @acme
```

#### Search items

검색어로 레지스트리를 찾습니다.

```bash
npx shadcn@latest search @acme --query button
```

#### View an item

이름으로 항목 하나를 봅니다.

```bash
npx shadcn@latest view @acme/button
```

#### Add an item

설치 흐름을 확인하려면 항목을 설치할 프로젝트에서 `add` 를 돌려 보세요.

```bash
npx shadcn@latest add @acme/button
```

자세한 내용은 [네임스페이스 레지스트리](/docs/registry/namespace) 문서를
보세요.

## Publish your registry

다른 개발자가 쓰게 하려면 프로젝트를 공개 주소에 올리세요. 배포하고 나면
사용자는 항목 주소로 바로 설치하거나, 자기 프로젝트에 네임스페이스로 등록해
쓸 수 있습니다.

### Share namespace setup instructions

`@acme/button` 같은 네임스페이스로 설치하게 하려면, 사용자에게 레지스트리 주소
템플릿을 프로젝트에 추가하라고 알려 주세요. CLI 가 항목을 풀 때 `{name}` 자리에
항목 이름이 들어갑니다.

템플릿은 항목 JSON 파일로 풀려야 합니다. 예를 들어 `@acme/button` 은
`https://acme.com/r/button.json` 이 됩니다. 카탈로그는 여전히
`https://acme.com/r/registry.json` 에서 따로 내보내야 합니다.

네임스페이스는 CLI 로 추가할 수 있습니다.

```bash
npx shadcn@latest registry add @acme=https://acme.com/r/{name}.json
```

또는 `components.json` 의 `registries` 필드에 직접 적어도 됩니다.

```json title="components.json" showLineNumbers
{
  "registries": {
    "@acme": "https://acme.com/r/{name}.json"
  }
}
```

그러면 사용자는 네임스페이스로 레지스트리 항목을 가져다 쓸 수 있습니다.

```bash
npx shadcn@latest add @acme/button
```

### Add your namespace to the registry index

레지스트리가 오픈소스이고 공개돼 있다면 공식 레지스트리 색인에 네임스페이스를
등록할 수 있습니다. 그러면 사용자가 전체 주소 템플릿을 붙여 넣지 않고 이름만으로
추가할 수 있습니다.

등록 요건은 [레지스트리 색인](/docs/registry/registry-index) 문서를 보세요.

## Guidelines

레지스트리에 올릴 컴포넌트를 만들 때 지킬 것들입니다.

- 항목은 `registry/[STYLE]/[NAME]` 에 두세요. 예시로 `default` 를 썼을 뿐이고, `registry` 아래에만 있으면 이름은 무엇이든 됩니다.
- 블록에는 `name`·`description`·`type`·`files` 가 반드시 있어야 합니다.
- 항목에 제대로 된 이름과 설명을 붙이는 편이 좋습니다. LLM 이 그 컴포넌트가 무엇이고 무엇에 쓰이는지 이해하는 데 도움이 됩니다.
- 레지스트리 의존성은 `registryDependencies` 에 빠짐없이 적으세요. 레지스트리 의존성은 `button`·`@acme/input-form`·`acme/ui/button`·`http://localhost:3000/r/editor.json` 같은 항목 주소입니다.
- 패키지 의존성은 `dependencies` 에 빠짐없이 적으세요. `zod`·`sonner` 처럼 레지스트리에 있는 패키지 이름입니다. 버전을 지정하려면 `zod@^3.20.0` 처럼 `name@version` 형식을 쓰면 됩니다.
- **import 는 항상 `@/registry` 경로를 쓰세요.** 예: `import { HelloWorld } from "@/registry/default/hello-world/hello-world"`
- 항목 안의 파일은 되도록 `components`·`hooks`·`lib` 디렉터리에 나눠 두세요.
