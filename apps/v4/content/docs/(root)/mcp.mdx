shadcn MCP 서버는 AI 어시스턴트가 레지스트리 항목을 다룰 수 있게 해 줍니다. 말로 시켜서 컴포넌트를 둘러보고, 찾고, 프로젝트에 바로 설치할 수 있습니다.

예를 들어 "acme 레지스트리의 컴포넌트로 랜딩 페이지를 만들어 줘" 나 "shadcn 레지스트리에서 로그인 폼을 찾아 줘" 라고 시킬 수 있습니다.

레지스트리는 프로젝트의 `components.json` 에서 설정합니다.

```json title="components.json" showLineNumbers
{
  "registries": {
    "@acme": "https://acme.com/r/{name}.json"
  }
}
```

## What is MCP?

[Model Context Protocol (MCP)](https://modelcontextprotocol.io) 은 AI 어시스턴트가 외부 데이터와 도구에 안전하게 연결하도록 하는 열린 규약입니다. shadcn MCP 서버를 쓰면 어시스턴트가 다음에 바로 닿습니다.

- **컴포넌트 둘러보기** — 설정된 레지스트리의 컴포넌트·블록·템플릿을 모두 나열합니다
- **여러 레지스트리 검색** — 이름이나 기능으로 여러 곳을 한 번에 찾습니다
- **말로 설치하기** — "로그인 폼 하나 넣어 줘" 같은 말로 컴포넌트를 추가합니다
- **여러 레지스트리 지원** — 공개 레지스트리, 사내 라이브러리, 서드파티 출처를 함께 씁니다

---

## How It Works

MCP 서버는 AI 어시스턴트와 컴포넌트 레지스트리, shadcn CLI 를 잇는 다리 역할을 합니다.

1. **레지스트리 연결** — MCP 가 설정된 레지스트리(Dropshot UI, 비공개, 서드파티)에 연결합니다
2. **말로 요청** — 필요한 것을 평범한 문장으로 설명합니다
3. **AI 처리** — 어시스턴트가 그 요청을 레지스트리 명령으로 옮깁니다
4. **자원 전달** — 자원을 받아 프로젝트에 설치합니다

---

## Supported Registries

shadcn MCP 서버는 shadcn 규격을 따르는 레지스트리라면 그대로 동작합니다.

- **기본 레지스트리** — Dropshot UI 컴포넌트가 모두 들어 있는 기본 레지스트리
- **서드파티 레지스트리** — shadcn 레지스트리 규격을 따르는 모든 레지스트리
- **비공개 레지스트리** — 사내 컴포넌트 라이브러리
- **네임스페이스 레지스트리** — `@namespace` 문법으로 설정한 여러 레지스트리

## Configuration

어떤 MCP 클라이언트로도 shadcn MCP 서버를 쓸 수 있습니다. 많이 쓰는 것들의 설정 방법입니다.

### Claude Code

Claude Code 에서 쓰려면 프로젝트의 `.mcp.json` 에 아래 설정을 넣으세요.

```json title=".mcp.json" showLineNumbers
{
  "mcpServers": {
    "shadcn": {
      "command": "npx",
      "args": ["shadcn@latest", "mcp"]
    }
  }
}
```

설정을 넣은 뒤 Claude Code 를 다시 시작하고 `/mcp` 를 실행하면 목록에 shadcn MCP 서버가 보입니다. `Connected` 라고 뜨면 준비된 것입니다.

자세한 내용은 [Claude Code MCP 문서](https://code.claude.com/docs/en/mcp)를 보세요.

### Cursor

Cursor 에서 설정하려면 프로젝트의 `.cursor/mcp.json` 에 shadcn 서버를 추가하세요.

```json title=".cursor/mcp.json" showLineNumbers
{
  "mcpServers": {
    "shadcn": {
      "command": "npx",
      "args": ["shadcn@latest", "mcp"]
    }
  }
}
```

설정을 넣은 뒤 Cursor 설정에서 shadcn MCP 서버를 켜세요.

켜면 MCP 서버 목록에서 shadcn 옆에 초록 점이 뜨고 쓸 수 있는 도구 목록이 보입니다.

자세한 내용은 [Cursor MCP 문서](https://docs.cursor.com/en/context/mcp#using-mcp-json)를 보세요.

### VS Code

GitHub Copilot 을 쓰는 VS Code 에서 설정하려면 프로젝트의 `.vscode/mcp.json` 에 shadcn 서버를 추가하세요.

```json title=".vscode/mcp.json" showLineNumbers
{
  "servers": {
    "shadcn": {
      "command": "npx",
      "args": ["shadcn@latest", "mcp"]
    }
  }
}
```

설정을 넣은 뒤 `.vscode/mcp.json` 을 열고 shadcn 서버 옆의 **Start** 를 누르세요.

자세한 내용은 [VS Code MCP 문서](https://code.visualstudio.com/docs/copilot/chat/mcp-servers)를 보세요.

### Codex

<Callout>
  **참고:** `shadcn` CLI 는 `~/.codex/config.toml` 을 자동으로 고치지 못합니다.
  설정을 직접 넣어야 합니다.
</Callout>

Codex 에서 설정하려면 `~/.codex/config.toml` 에 shadcn 서버를 추가하세요.

```toml title="~/.codex/config.toml" showLineNumbers
[mcp_servers.shadcn]
command = "npx"
args = ["shadcn@latest", "mcp"]
```

설정을 넣은 뒤 Codex 를 다시 시작하면 MCP 서버가 올라옵니다.

## Configuring Registries

MCP 서버는 프로젝트의 `components.json` 설정으로 여러 레지스트리를 지원합니다. 비공개 레지스트리와 서드파티를 포함한 여러 곳의 컴포넌트에 닿을 수 있습니다.

`components.json` 에 레지스트리를 더 설정합니다.

```json title="components.json" showLineNumbers
{
  "registries": {
    "@acme": "https://registry.acme.com/{name}.json",
    "@internal": {
      "url": "https://internal.company.com/{name}.json",
      "headers": {
        "Authorization": "Bearer ${REGISTRY_TOKEN}"
      }
    }
  }
}
```

<Callout>
  **참고:** 기본 shadcn/ui 레지스트리는 따로 설정하지 않아도 됩니다.
</Callout>

## Authentication

인증이 필요한 비공개 레지스트리라면 `.env.local` 에 환경 변수를 넣으세요.

```bash title=".env.local"
REGISTRY_TOKEN=your_token_here
API_KEY=your_api_key_here
```

레지스트리 인증에 대한 자세한 내용은 [인증 문서](/docs/registry/authentication)를 보세요.

## Troubleshooting

### MCP Not Responding

MCP 서버가 응답하지 않는다면 이렇게 확인하세요.

1. **설정 확인** — MCP 클라이언트에 서버가 제대로 설정되고 켜져 있는지 봅니다
2. **클라이언트 재시작** — 설정을 바꿨다면 클라이언트를 다시 시작합니다
3. **설치 확인** — 프로젝트에 `shadcn` 이 설치돼 있는지 봅니다
4. **네트워크 확인** — 설정한 레지스트리에 닿는지 확인합니다

### Registry Access Issues

레지스트리에서 컴포넌트를 못 불러온다면 이렇게 확인하세요.

1. **components.json 확인** — 레지스트리 주소가 맞는지 봅니다
2. **인증 확인** — 비공개 레지스트리용 환경 변수가 설정돼 있는지 봅니다
3. **레지스트리 확인** — 레지스트리가 켜져 있고 닿는지 확인합니다
4. **네임스페이스 확인** — 문법이 맞는지 봅니다(`@namespace/component`)

### Installation Failures

컴포넌트 설치가 실패한다면 이렇게 확인하세요.

1. **프로젝트 설정 확인** — 올바른 `components.json` 이 있는지 봅니다
2. **경로 확인** — 대상 디렉터리가 있는지 봅니다
3. **권한 확인** — 컴포넌트 디렉터리에 쓰기 권한이 있는지 봅니다
4. **의존성 확인** — 필요한 의존성이 설치돼 있는지 봅니다

### No Tools or Prompts

`No tools or prompts` 메시지가 뜬다면 이렇게 해 보세요.

1. **npx 캐시 지우기** — `npx clear-npx-cache` 를 돌립니다
2. **MCP 서버 다시 켜기** — 클라이언트에서 서버를 껐다 켭니다
3. **로그 보기** — Cursor 라면 View → Output 에서 `MCP: project-*` 를 고르면 로그가 보입니다.
