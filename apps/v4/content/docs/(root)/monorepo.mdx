지금까지 모노레포에서 shadcn/ui 를 쓰는 건 번거로웠습니다. CLI 로 컴포넌트를
추가할 수는 있었지만 어디에 설치할지 직접 챙기고 import 경로도 손으로
고쳐야 했습니다.

CLI 에 모노레포 지원이 들어가면서 훨씬 수월해졌습니다.

이제 CLI 가 모노레포 구조를 이해해서 컴포넌트와 의존성, 레지스트리 의존성을
알맞은 경로에 설치하고 import 도 알아서 처리합니다.

## Getting started

<Steps>

### Create a new monorepo project

새 모노레포 프로젝트를 만들려면 `init` 에 `--monorepo` 플래그를 줍니다.

```bash
npx shadcn@latest init --monorepo
```

그다음 쓰고 싶은 템플릿을 고릅니다.

```bash
? Select a template ›
❯   Next.js
    Vite
    TanStack Start
    React Router
    Astro
```

그러면 `web` 과 `ui` 두 워크스페이스를 가진 모노레포가 만들어지고 빌드 시스템으로
[Turborepo](https://turbo.build/repo/docs) 가 들어갑니다.

설정이 다 돼 있으니 바로 컴포넌트를 추가하면 됩니다.

### Add components to your project

컴포넌트를 추가하려면 **앱 경로 안에서** `add` 명령을 돌리세요.

```bash
cd apps/web
```

```bash
npx shadcn@latest add [COMPONENT]
```

CLI 가 어떤 종류의 컴포넌트인지 알아내어 알맞은 파일을 알맞은 경로에
설치합니다.

예를 들어 `npx shadcn@latest add button` 을 돌리면 button 컴포넌트가 `packages/ui` 아래에 설치되고 `apps/web` 의 import 경로가 갱신됩니다.

`npx shadcn@latest add login-01` 을 돌리면 `button`·`label`·`input`·`card` 는 `packages/ui` 아래에, `login-form` 은 `apps/web/components` 아래에 설치됩니다.

### Importing components

`@workspace/ui` 패키지에서 컴포넌트를 이렇게 가져옵니다.

```tsx
import { Button } from "@workspace/ui/components/button"
```

훅과 유틸리티도 `@workspace/ui` 패키지에서 가져올 수 있습니다.

```tsx
import { useTheme } from "@workspace/ui/hooks/use-theme"
import { cn } from "@workspace/ui/lib/utils"
```

</Steps>

## File Structure

새 모노레포를 만들면 CLI 가 아래 구조를 만들어 줍니다.

```txt
apps
└── web         # Your app goes here.
    ├── app
    │   └── page.tsx
    ├── components
    │   └── login-form.tsx
    ├── components.json
    └── package.json
packages
└── ui          # Your components and dependencies are installed here.
    ├── src
    │   ├── components
    │   │   └── button.tsx
    │   ├── hooks
    │   ├── lib
    │   │   └── utils.ts
    │   └── styles
    │       └── globals.css
    ├── components.json
    └── package.json
package.json
turbo.json
```

## Requirements

1. 모든 워크스페이스에 `components.json` 이 있어야 합니다. `package.json` 이 npm 에 의존성 설치 방법을 알려 주듯, `components.json` 은 CLI 에 컴포넌트를 어떻게 어디에 설치할지 알려 줍니다.

2. `components.json` 에 워크스페이스 별칭이 제대로 정의돼 있어야 합니다. 그래야 CLI 가 컴포넌트·훅·유틸리티를 어떻게 가져올지 압니다.

```json showLineNumbers title="apps/web/components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "base-nova",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "../../packages/ui/src/styles/globals.css",
    "baseColor": "neutral",
    "cssVariables": true
  },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "@/components",
    "hooks": "@/hooks",
    "lib": "@/lib",
    "utils": "@workspace/ui/lib/utils",
    "ui": "@workspace/ui/components"
  }
}
```

```json showLineNumbers title="packages/ui/components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json",
  "style": "base-nova",
  "rsc": true,
  "tsx": true,
  "tailwind": {
    "config": "",
    "css": "src/styles/globals.css",
    "baseColor": "neutral",
    "cssVariables": true
  },
  "iconLibrary": "lucide",
  "aliases": {
    "components": "@workspace/ui/components",
    "utils": "@workspace/ui/lib/utils",
    "hooks": "@workspace/ui/hooks",
    "lib": "@workspace/ui/lib",
    "ui": "@workspace/ui/components"
  }
}
```

3. 두 `components.json` 의 `style`·`iconLibrary`·`baseColor` 를 같게 맞추세요.

4. **Tailwind CSS v4 라면 `components.json` 의 `tailwind` 설정을 비워 두세요.**

이 조건을 지키면 CLI 가 UI 컴포넌트·블록·lib·훅을 알맞은 경로에 설치하고 import 도 알아서 처리합니다.

<Callout className="mt-6">
  `package.json#imports` 는 `packages/ui` 처럼 워크스페이스 안에서만 쓰는 별칭에
  잘 맞습니다. `@workspace/ui/components` 같은 공용 import 는 `components.json`
  에 별칭을 그대로 두세요. CLI 가 워크스페이스 경계를 넘어 파일을 보낼 때 그
  별칭을 씁니다.
</Callout>

## Using `package.json#imports`

패키지 import 를 쓰고 `tsconfig.json` 의 `paths` 에 기대지 않는 모노레포라면
이렇게 하세요.

- 워크스페이스 안의 파일에는 로컬 `#...` 별칭
- `@workspace/ui/components` 같은 공용 import 에는 워크스페이스 패키지의
  `exports`

예를 들어 앱 워크스페이스는 로컬 패키지 import 를 쓸 수 있습니다.

```json showLineNumbers title="apps/web/package.json"
{
  "name": "web",
  "private": true,
  "type": "module",
  "imports": {
    "#components/*": "./src/components/*.tsx",
    "#lib/*": "./src/lib/*.ts",
    "#hooks/*": "./src/hooks/*.ts"
  },
  "dependencies": {
    "@workspace/ui": "workspace:*"
  }
}
```

```json showLineNumbers title="apps/web/components.json"
{
  "aliases": {
    "components": "#components",
    "ui": "@workspace/ui/components",
    "lib": "#lib",
    "hooks": "#hooks",
    "utils": "@workspace/ui/lib/utils"
  }
}
```

그리고 공용 UI 패키지는 `exports` 로 설치 대상을 노출합니다.

```json showLineNumbers title="packages/ui/package.json"
{
  "name": "@workspace/ui",
  "private": true,
  "type": "module",
  "imports": {
    "#components/*": "./src/components/*.tsx",
    "#lib/*": "./src/lib/*.ts",
    "#hooks/*": "./src/hooks/*.ts"
  },
  "exports": {
    "./globals.css": "./src/styles/globals.css",
    "./components/*": "./src/components/*.tsx",
    "./lib/*": "./src/lib/*.ts",
    "./hooks/*": "./src/hooks/*.ts"
  }
}
```

```json showLineNumbers title="packages/ui/components.json"
{
  "aliases": {
    "components": "#components",
    "ui": "#components",
    "lib": "#lib",
    "hooks": "#hooks",
    "utils": "#lib/utils"
  }
}
```

이 구성에서는 이렇게 동작합니다.

- 앱에서 공용 UI 패키지로 추가되는 파일은 `@workspace/ui/...` 를 거칩니다
- `packages/ui` 안에서 추가되는 파일은 패키지 로컬 `#...` 별칭을 씁니다
- 다른 워크스페이스가 참조하는 경로는 공용 패키지가 반드시 export 해야 합니다

프레임워크별 패키지 import 설정은 [패키지 import 문서](/docs/package-imports)를 보세요.
