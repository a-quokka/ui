**컴포넌트 라이브러리가 아닙니다. 여러분의 컴포넌트 라이브러리를 만드는 방식입니다.**

보통의 컴포넌트 라이브러리는 이렇게 씁니다. NPM 에서 패키지를 설치하고, 컴포넌트를 import 하고, 앱에서 가져다 씁니다.

이 방식은 디자인 시스템에 맞게 컴포넌트를 고쳐야 하거나 라이브러리에 없는 컴포넌트가 필요해지는 순간 막힙니다. **결국 라이브러리 컴포넌트를 감싸거나, 스타일을 덮으려고 우회 코드를 쓰거나, API 가 서로 안 맞는 라이브러리를 섞어 쓰게 됩니다.**

Dropshot UI 는 그 문제를 풉니다. 다음 원칙 위에 서 있습니다.

- **열린 코드:** 컴포넌트 코드의 가장 바깥 층이 고칠 수 있도록 열려 있습니다.
- **조합:** 모든 컴포넌트가 같은 방식으로 조합됩니다. 그래서 예측할 수 있습니다.
- **배포:** 평평한 파일 스키마와 명령줄 도구로 컴포넌트를 쉽게 나눠 씁니다.
- **좋은 기본값:** 기본 스타일을 정성껏 골라 뒀습니다. 손대지 않아도 보기 좋습니다.
- **AI 친화:** 코드가 열려 있어 LLM 이 읽고, 이해하고, 고칠 수 있습니다.

## Open Code

Dropshot UI 는 컴포넌트 코드를 그대로 넘겨줍니다. 필요에 맞게 고치고 넓히는 권한이 전부 여러분에게 있습니다. 그래서 이런 것이 가능합니다.

- **완전히 투명합니다:** 각 컴포넌트가 어떻게 만들어졌는지 그대로 보입니다.
- **고치기 쉽습니다:** 디자인과 기능 요구에 맞게 컴포넌트의 어느 부분이든 바꿀 수 있습니다.
- **AI 와 잘 맞습니다:** 코드에 닿을 수 있으니 LLM 이 읽고 이해하고 개선하기 쉽습니다.

_보통의 라이브러리에서 버튼 동작을 바꾸려면 스타일을 덮거나 컴포넌트를 감싸야 합니다. Dropshot UI 에서는 버튼 코드를 그냥 고치면 됩니다._

## Composition

Dropshot UI 의 모든 컴포넌트는 같은 조합 방식을 공유합니다. **없는 컴포넌트는 가져와서 조합할 수 있게 만들고, 나머지 디자인 시스템과 어울리도록 스타일을 맞춥니다.**

_조합 방식이 같으면 팀에도 LLM 에도 예측 가능해집니다. 새 컴포넌트마다 다른 API 를 익힐 필요가 없습니다. 서드파티 컴포넌트라도 마찬가지입니다._

## Distribution

Dropshot UI 는 코드 배포 시스템이기도 합니다. 컴포넌트를 위한 스키마와 그것을 나르는 CLI 를 정의합니다.

- **스키마:** 컴포넌트와 그 의존성·속성을 정의하는 평평한 파일 구조입니다.
- **CLI:** 프로젝트 사이로 컴포넌트를 나르고 설치하는 명령줄 도구입니다. 여러 프레임워크를 지원합니다.

_이 스키마로 컴포넌트를 다른 프로젝트에 배포할 수도 있고, 기존 스키마를 바탕으로 AI 가 새 컴포넌트를 만들게 할 수도 있습니다._

## Beautiful Defaults

Dropshot UI 에는 기본 스타일을 정성껏 고른 컴포넌트가 많습니다. 하나만 놓아도 보기 좋고, 여럿을 함께 놓아도 하나의 시스템으로 어울립니다.

- **기본값이 좋습니다:** 손대지 않아도 화면이 깔끔하고 군더더기 없습니다.
- **디자인이 통일돼 있습니다:** 컴포넌트끼리 자연스럽게 어울립니다. 서로 맞도록 만들어져 화면이 흐트러지지 않습니다.
- **고치기 쉽습니다:** 바꾸고 싶은 게 있으면 기본값을 덮거나 넓히면 됩니다.

## AI-Ready

Dropshot UI 의 설계는 AI 도구가 코드를 다루기 좋게 돼 있습니다. 코드가 열려 있고 API 가 일관돼서 AI 모델이 읽고, 이해하고, 새 컴포넌트를 만들어 낼 수 있습니다.

_AI 모델이 여러분의 컴포넌트가 어떻게 동작하는지 익히고, 개선을 제안하거나 기존 디자인에 맞는 새 컴포넌트를 만들어 줄 수 있습니다._
