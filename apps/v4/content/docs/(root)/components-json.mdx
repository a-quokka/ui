`components.json` 에는 프로젝트 설정이 들어 있습니다.

이 파일로 프로젝트가 어떻게 구성돼 있는지, 컴포넌트를 어떻게 맞춰 만들지 판단합니다.

<Callout className="mt-6" title="Note: The `components.json` file is optional">
  **CLI 로 컴포넌트를 추가할 때만 필요합니다.** 복사해 붙여 넣는 방식이라면 이
  파일은 없어도 됩니다.
</Callout>

아래 명령으로 프로젝트에 `components.json` 을 만들 수 있습니다.

```bash
npx shadcn@latest init
```

자세한 내용은 <Link href="/docs/cli">CLI 문서</Link>를 보세요.

## $schema

`components.json` 의 JSON 스키마는 [여기](https://ui.shadcn.com/schema.json)에서 볼 수 있습니다.

```json title="components.json"
{
  "$schema": "https://ui.shadcn.com/schema.json"
}
```

## style

컴포넌트 스타일입니다. **초기화한 뒤에는 바꿀 수 없습니다.**

```json title="components.json"
{
  "style": "new-york"
}
```

`default` 스타일은 더 이상 쓰지 않습니다. `new-york` 을 쓰세요.

## tailwind

프로젝트에 Tailwind CSS 가 어떻게 설정돼 있는지 CLI 에 알려 주는 설정입니다.

Tailwind CSS 설정 방법은 <Link href="/docs/installation">설치 문서</Link>를 보세요.

### tailwind.config

`tailwind.config.js` 의 경로입니다. **Tailwind CSS v4 라면 비워 두세요.**

```json title="components.json"
{
  "tailwind": {
    "config": "tailwind.config.js" | "tailwind.config.ts"
  }
}
```

### tailwind.css

Tailwind CSS 를 불러오는 CSS 파일의 경로입니다.

```json title="components.json"
{
  "tailwind": {
    "css": "styles/global.css"
  }
}
```

### tailwind.baseColor

컴포넌트의 기본 테마 토큰을 만들 때 씁니다. **초기화한 뒤에는 바꿀 수 없습니다.**

```json title="components.json"
{
  "tailwind": {
    "baseColor": "neutral" | "stone" | "zinc" | "mauve" | "olive" | "mist" | "taupe"
  }
}
```

### tailwind.cssVariables

테마에는 CSS 변수를 쓰고, 또 권합니다.

`tailwind.cssVariables` 를 `true` 로 두면 `background`·`foreground`·`primary` 같은 의미 단위 토큰이 만들어집니다. `false` 로 두면 Tailwind 색상 유틸리티가 직접 박힙니다.

```json title="components.json"
{
  "tailwind": {
    "cssVariables": `true` | `false`
  }
}
```

자세한 내용은 <Link href="/docs/theming">테마 문서</Link>를 보세요.

**초기화한 뒤에는 바꿀 수 없습니다.** CSS 변수와 유틸리티 클래스 사이를 오가려면 컴포넌트를 지우고 다시 설치해야 합니다.

### tailwind.prefix

Tailwind CSS 유틸리티 클래스에 붙일 접두사입니다. 이 접두사가 붙은 채로 컴포넌트가 추가됩니다.

```json title="components.json"
{
  "tailwind": {
    "prefix": "tw-"
  }
}
```

## rsc

React Server Components 지원 여부입니다.

`true` 로 두면 CLI 가 클라이언트 컴포넌트에 `use client` 를 알아서 붙입니다.

```json title="components.json"
{
  "rsc": `true` | `false`
}
```

## tsx

컴포넌트를 TypeScript 로 받을지 JavaScript 로 받을지 고릅니다.

`false` 로 두면 컴포넌트가 `.jsx` 확장자의 JavaScript 로 추가됩니다.

```json title="components.json"
{
  "tsx": `true` | `false`
}
```

## aliases

CLI 는 이 값으로 컴포넌트를 알맞은 자리에 두고 import 를 고쳐 씁니다.

별칭은 둘 중 하나로 뒷받침할 수 있습니다.

1. `tsconfig.json` 이나 `jsconfig.json` 의 `compilerOptions.paths`
2. TypeScript 패키지 import 해석을 켠 `package.json#imports`

CLI 를 쓴다면 `components.json` 의 별칭은 여전히 필요합니다. 어떤 import 루트가 `components`·`ui`·`lib`·`hooks`·`utils` 에 해당하는지 알려 주기 때문입니다.

<Callout className="mt-6">
  **중요:** 패키지 import 를 쓴다면 `tsconfig.json` 에서
  `resolvePackageJsonImports` 를 켜고 `moduleResolution: "bundler"` 를 쓰세요.
  `paths` 를 쓴다면 해당하는 경우 별칭에 `src` 디렉터리를 포함해야 합니다.
</Callout>

### Using `tsconfig` or `jsconfig` paths

```json title="tsconfig.json"
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["./src/*"]
    }
  }
}
```

### Using `package.json#imports`

패키지가 하나인 앱에 권하는 설정입니다.

```json title="package.json"
{
  "imports": {
    "#components/*": "./src/components/*.tsx",
    "#lib/*": "./src/lib/*.ts",
    "#hooks/*": "./src/hooks/*.ts"
  }
}
```

```json title="tsconfig.json"
{
  "compilerOptions": {
    "moduleResolution": "bundler",
    "resolvePackageJsonImports": true
  }
}
```

```json title="components.json"
{
  "aliases": {
    "components": "#components",
    "ui": "#components/ui",
    "lib": "#lib",
    "hooks": "#hooks",
    "utils": "#lib/utils"
  }
}
```

`components.json` 의 별칭은 여전히 `components`·`ui`·`lib`·`hooks`·`utils` 를
어디에 둘지 CLI 에 알려 줍니다. `package.json#imports` 는 그 `#...` 지정자를
런타임과 TypeScript 에서 풀어 줍니다.

어떤 `imports` 대상에 맞았는지에 따라 생성된 `#...` import 가 확장자를 남길지도
결정됩니다.

- `"#components/*": "./src/components/*"` 는 원본 확장자를 남기고
  `#components/button.tsx` 같은 import 를 만듭니다
- `"#components/*": "./src/components/*.tsx"` 는 확장자를 떼고
  `#components/button` 같은 import 를 만듭니다

모노레포는 <Link href="/docs/monorepo">모노레포 문서</Link>를 보세요. 로컬
워크스페이스 별칭에는 `package.json#imports` 를 쓸 수 있고,
`@workspace/ui/components` 같은 공용 워크스페이스 import 는 대상 패키지의
`exports` 에서 풀립니다.

프레임워크별 설정은 [패키지 import 문서](/docs/package-imports)를 보세요.

### aliases.utils

유틸리티 함수의 import 별칭입니다.

```json title="components.json"
{
  "aliases": {
    "utils": "@/lib/utils"
  }
}
```

### aliases.components

컴포넌트의 import 별칭입니다.

```json title="components.json"
{
  "aliases": {
    "components": "@/components"
  }
}
```

### aliases.ui

`ui` 컴포넌트의 import 별칭입니다.

CLI 는 `aliases.ui` 값으로 `ui` 컴포넌트를 어디에 둘지 정합니다. `ui` 컴포넌트의 설치 위치를 바꾸고 싶을 때 씁니다.

```json title="components.json"
{
  "aliases": {
    "ui": "@/app/ui"
  }
}
```

### aliases.lib

`format-date`·`generate-id` 같은 `lib` 함수의 import 별칭입니다.

```json title="components.json"
{
  "aliases": {
    "lib": "@/lib"
  }
}
```

### aliases.hooks

`use-media-query`·`use-toast` 같은 `hooks` 의 import 별칭입니다.

```json title="components.json"
{
  "aliases": {
    "hooks": "@/hooks"
  }
}
```

## registries

프로젝트에 여러 레지스트리를 설정합니다. 그러면 비공개 레지스트리를 포함한 여러 곳에서 컴포넌트·라이브러리·유틸리티 같은 자원을 설치할 수 있습니다.

자세한 내용은 <Link href="/docs/registry/namespace">네임스페이스 레지스트리</Link> 문서를 보세요.

### Basic Configuration

URL 템플릿으로 레지스트리를 설정합니다.

```json title="components.json"
{
  "registries": {
    "@v0": "https://v0.dev/chat/b/{name}",
    "@acme": "https://registry.acme.com/{name}.json",
    "@internal": "https://internal.company.com/{name}.json"
  }
}
```

설치할 때 `{name}` 자리에 자원 이름이 들어갑니다.

### Advanced Configuration with Authentication

인증이 필요한 비공개 레지스트리라면 이렇게 씁니다.

```json title="components.json"
{
  "registries": {
    "@private": {
      "url": "https://api.company.com/registry/{name}.json",
      "headers": {
        "Authorization": "Bearer ${REGISTRY_TOKEN}",
        "X-API-Key": "${API_KEY}"
      },
      "params": {
        "version": "latest"
      }
    }
  }
}
```

`${VAR_NAME}` 형식으로 쓴 환경 변수는 실행 환경에서 자동으로 채워집니다.

### Using Namespaced Registries

설정해 두면 네임스페이스 문법으로 자원을 설치합니다.

```bash
# Install from a configured registry
npx shadcn@latest add @v0/dashboard

# Install from private registry
npx shadcn@latest add @private/button

# Install multiple resources
npx shadcn@latest add @acme/header @internal/auth-utils
```

### Example: Multiple Registry Setup

```json title="components.json"
{
  "registries": {
    "@shadcn": "https://ui.shadcn.com/r/{name}.json",
    "@company-ui": {
      "url": "https://registry.company.com/ui/{name}.json",
      "headers": {
        "Authorization": "Bearer ${COMPANY_TOKEN}"
      }
    },
    "@team": {
      "url": "https://team.company.com/{name}.json",
      "params": {
        "team": "frontend",
        "version": "${REGISTRY_VERSION}"
      }
    }
  }
}
```

이 설정으로 이런 것이 가능합니다.

- Dropshot UI 의 공개 컴포넌트를 설치합니다
- 인증을 거쳐 사내 비공개 UI 컴포넌트에 접근합니다
- 버전이 붙은 팀 전용 자원을 씁니다

인증에 대한 자세한 내용은 <Link href="/docs/registry/authentication">인증</Link> 문서를 보세요.
